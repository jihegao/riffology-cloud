# ADR: production model supply behind the Riffology Model Proxy

Date / official documentation checked: **2026-09-14**. Related: [#46](https://github.com/jihegao/riffology-cloud/issues/46), parent #28. Status: **proposed; Phase A preparation only**. Code inspected at `d5d53de`; no account entitlement, live throughput, price quote, or model-quality benchmark was measured. This document does not complete Phase B/C or authorize a purchase/deployment.

## Decision and existing boundary

Evaluate **Cloudflare AI Gateway provider-native OpenAI Responses with platform-owned provider credentials first**. Prefer explicit provider credentials held by Model Proxy for the initial BYOK evaluation, so billing does not silently depend on a missing stored key. Compare the same account/model directly as a control when a bounded paid evaluation is authorized. This is a compatibility-based candidate, not a quality/cost winner or a selected production model. Keep one accepted production path/model; no automatic routing or fallback.

Current facts from the repository:

- `services/model-proxy/release.ts` constructs only `OpenCodeGoResponsesProvider`, behind `M2_MODEL_PROVIDER_ENABLED`. `infra/wrangler.phase1-staging.jsonc` declares `opencode-go` / `gpt-5.6-luna`, a named provider secret, and token policy `m2-token-vertical-v2`. These are tracked configuration facts, not verified live account state; no secret values were read.
- `services/trusted-pi/product-model-transport.mjs` requires `openai-responses`, the internal proxy URL, `stream:true`, `store:false`, and text-only payloads. It supplies stable call/request IDs and a bounded payload. Provider/model authority is pinned by Turn capability, not chosen by the browser.
- `services/model-proxy/http.ts` exposes `ProductModelProvider.dispatch`: fixed provider/model, pseudonymous session ID, request identity, bounded payload, deadline/signal in; status, provider request ID, usage, content type, bounded bytes out. Its `providerSessionId` derivation still uses an OpenCode-specific domain string: preserve it for legacy calls; do not send the OpenCode session header to a different provider.
- `opencode-go-responses.ts` buffers the entire SSE, validates terminal usage, then the proxy commits budget state before returning bytes. This is not incremental end-to-end streaming. Missing/malformed usage on success takes the unknown path. Transport completion (including `response.incomplete`) is not proof of a successful modeling task.
- `services/model-budget/core.ts` provides tenant-scoped durable, **per-Turn token admission**, dispatch-once fencing and held/pending unknown outcomes. It does not implement money prices, account balances, per-user or tenant-period spending limits, or a global budget authority. The model-proxy README's older “no provider adapter” statement is superseded by the release implementation above.

Record model context/output limits, RPM/TPM and account concurrency in the evaluation manifest; provider quotas and Gateway logging limits are different constraints. No fixed throughput or token-price constants are selected here.

OpenAI API data is not used for training by default; standard abuse-monitoring retention can include content for up to 30 days with stated exceptions. `store:false` does not itself confer ZDR; model-specific caching and application-state exceptions must be reviewed for the chosen account/model. See [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data). For Gateway, disable payload storage (`cf-aig-collect-log-payload:false`) and caching for the initial path; separately bound metadata retention/access and disable content-bearing debug telemetry. [Payload logging control](https://developers.cloudflare.com/changelog/post/2026-03-17-collect-log-payload-header/), [logging settings](https://developers.cloudflare.com/ai-gateway/observability/logging/). Do not describe this as entire-chain zero retention without account evidence.

## Phase B implementation contract

1. Add a server-owned provider profile separating **inference provider**, **model**, **protocol**, **gateway**, **billing mode**, and policy/version. Only an allowlisted endpoint and secret references are configurable. Missing or incompatible profiles fail closed before reservation. Keep the current OpenCode profile for legacy Turns; resolve one versioned profile at admission and persist its identifier with the reservation so later configuration changes cannot redirect an in-flight call.
2. Implement the selected Responses adapter behind `ProductModelProvider`, preserving the current buffered contract and response bound. Do not rename legacy identities, weaken payload/credential validation, expose upstream errors, or change Tool/Revision/Experiment semantics. Factor protocol parsing only where fixture coverage proves equivalence. Keep long-lived credentials in trusted server secrets, never capability payloads, project files or exports.
3. Preserve the existing durable call fence and token ledger. Add conservative **monetary reservation** with a versioned rate card, including cached/uncached input and billable reasoning/output semantics where applicable. Gate admission on Turn, authenticated-user, tenant-period and global-period caps, plus provider disable/circuit state. Use a single durable spending authority for the initial production scale; derive user identity server-side. Reserve money before token dispatch; release only with proof of no dispatch. A crash between authorities holds the monetary reservation for reconciliation rather than releasing it on elapsed time. No UI balance/payment system is required.
4. Persist normalized error categories: rejected auth/config, rate limited, provider failure, deadline, cancellation, malformed stream, missing usage, outcome unknown. Log sanitized route version, request/response IDs, timing and usage quality; join tenant/project/workspace/Turn internally using opaque correlation references. Never log complete prompts, source files, tool payloads, capabilities, credentials or raw upstream error text by default.
5. Disable automatic SDK/Gateway/adapter retries, Gateway caching and provider fallback for this path. A request correlation header is **not** proof of upstream deduplication. Cancellation/timeout after dispatch may still incur cost; hold unknown usage conservatively. Replaying the same platform call remains observe-only. Operator reconciliation must attach account/provider evidence to the existing call and be idempotent; a network timeout or missing response is never permission to create a replacement request identity. Provider disable stops new calls while historical reads continue.

This scope adds private configuration, ledger metadata and operations controls; it adds no public model-selection API. Migrations must be additive: old reservations keep their original route identity and token facts; new monetary/profile fields cannot reinterpret historic charges.

## Paid benchmark and release acceptance

Prepare a manifest before any live calls: code/runtime SHA, selected account/model/profile/version, dated rate card and currency, privacy settings, per-call/Turn/global hard evaluation cap, concurrency ladder, operator, deadline and stop conditions. The account owner must supply model access, budget and paid-run authorization; none are inferred from an existing development secret. No measurements in this ADR claim to satisfy these gates.

Use a fixed six-task suite, three isolated runs each, with identical prompts/tool contracts and reset ordinary-user projects: (1) create a queue model and Spec, (2) change a parameter without source drift, (3) add a mechanism and update Spec, (4) repair a seeded Python validation failure, (5) run baseline/intervention experiments and cite persisted metrics, (6) reopen a saved multi-Turn project and extend it. Freeze inputs and expected domain checks before comparing candidates. Build source, tool-event, Revision, Run and Python-result evidence for every attempt; failed/cancelled attempts remain in the denominator.

Record task and first-attempt pass rate, tool errors/repairs, input/cached/output/reasoning usage where available, elapsed Turn time (p50/p95), provider errors, total verified cost and `total_model_cost / accepted_tasks` (undefined when none pass). Include failed attempts and credit fees; keep unknown costs separately held and do not declare a cost winner until reconciled. Proposed minimum functional gate: at least 16/18 tasks pass, every task category passes at least twice, and zero fabricated execution claims or credential/tool-boundary violations. This threshold is a release proposal, not a statistical quality guarantee. Latency/cost/concurrency targets require product-owner values in the manifest before execution.

Local fixtures must cover valid tool calls/results and reasoning/text, split SSE frames, incomplete terminal, malformed/oversized body, 401/403/429/5xx, timeout, cancel before/after dispatch, stream interruption, missing/invalid usage, response loss after budget finish, failed reconciliation and route change. Assert at most one provider dispatch and no tool side-effect replay for a stable call; user/tenant/global caps and provider stop must deny new dispatches while saved histories remain readable. Run targeted Model Proxy/Model Budget/Trusted Pi suites, then full `npm run check` for the release candidate.

Live acceptance must additionally verify ordinary-user browser flow → actual project tools → Python validation → saved Revision → reopen/continue, using durable artifacts rather than a provider-list or text-response smoke test. Exercise bounded account-approved concurrency and recovery; record limits actually observed. Reconcile platform ledger against provider/Gateway usage. Enable only the accepted route/model, with a tested server-side stop switch; rollback affects new calls only and keeps unknown calls held.

## Unresolved release inputs

- Platform-owned production account/model entitlement, service suitability for public operation, and approved secret provisioning. Current preview config does not prove these facts.
- Explicit paid evaluation authorization and maximum spend; production user/tenant/global caps, target latency/concurrency and alert thresholds.
- Required privacy/residency policy and verified account settings (including model caching, Gateway logs and upstream abuse monitoring/ZDR). Any unacceptable retention blocks that route.
- Measured benchmark and protocol results. Select the default model only after these exist; update this ADR with the winning route and evidence. If current preview supply fails confirmed public-operation constraints, elevate the minimum replacement path to a release blocker without making Cloudflare adoption itself mandatory.
