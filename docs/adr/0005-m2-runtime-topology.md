# ADR 0005：M2 可信 Pi 与项目执行使用两个 Sandbox

状态：Accepted，2026-09-06。

2026-09-07 的[真实产品 Turn 本地证据](../evidence/runs/m2-product-turn-provider-disabled-20260907012455020/primary-review.json)用独立 `services/runtime/Dockerfile.cloud`、Project Tool Sandbox 与 Trusted Pi Sandbox 跑通当前产品 release assembly：项目初始化后，首轮 provider 关闭 Turn 明确记录 503，冻结文件与 Pi Session、写入 R2 Revision 并提交失败终态；随后删除首轮两个 Sandbox，第二轮在新 actor 中从首轮 workspace 与 Session receipt 恢复，保持文件摘要、推进 Session 摘要并保存下一 Revision。再次删除两个 Sandbox 及第二轮 Session blob 后，第三轮在分配 Sandbox 前终止为 `turn-base-unavailable`，不创建新 Revision。三轮在 Workerd 重启后保持相同终态；预算和外部 Worker fetch 均为 0，容器全部清理。验收只在生成镜像内启用候选 release；产品配置测试继续禁止 `m0-*` 和 `Dockerfile.local`，两个发布开关与活动 Trusted Pi release 均保持失败关闭。

## 决策

每个活动 Workspace 的 M2 执行由 WorkspaceAgent 选择两个不同的 Sandbox actor：可信 Pi Sandbox 和项目 Sandbox。名称从平台持有的 Workspace generation、Turn 和 dispatch identity 派生，浏览器、项目代码和 Pi 工具参数均不能提供 Sandbox ID。

可信 Pi Sandbox 固定包含锁定版本的 Pi SDK、Simulation Skill 与平台代理客户端，不挂载项目 `/workspace`，不持有 R2 主凭据、供应商密钥或跨项目寻址能力。它只有两个固定出站目的：Model Proxy 和 Tool Bridge；真实供应商凭据留在 Worker/Model Proxy。

项目 Sandbox 持有当前项目 `/workspace`，包含固定 Python、SimPy 与允许的应用运行依赖，不包含 Pi SDK、Pi Session、模型 capability 或平台控制模块。项目 Shell 只在该 VM 内执行；默认无互联网，后续依赖安装只能使用服务端固定清单或经过摘要校验的受控来源。

Sandbox actor ID 使用平台校验后的 scope、Turn 与 dispatch identity 计算完整 SHA-256，再编码为 lowercase base32，并分别加 `m2-t-` / `m2-p-` 角色前缀。两个 ID 长度均为 57，浏览器、Pi 输出和 Tool 参数均不参与寻址。可信出站 handler 只接受 `https://model-proxy.riffology.internal/v1/responses` 与 `https://tool-bridge.riffology.internal/v1/tool` 的 POST，移除来路 Authorization、Cookie 与身份头后重建内部身份；目的 host 使用固定常量，不从 binding 名称推导。

WorkspaceAgent 是 Turn、command intent、event sequence、Revision pointer 与取消 fence 的单写者。Tool Bridge 只接受绑定 `tenant + project + workspace + generation + turn + dispatch + command` 的平台命令。路径必须是 `/workspace` 下的规范相对路径，并拒绝 `.riffology` 平台目录。项目输出永远不能签发终态、停止证明、Checkpoint receipt 或新 capability。

WorkspaceAgent 同时承载 Workspace provisioning watchdog 与 Turn reconciliation，但一个 Durable Object 只有一个物理 alarm。两类流程分别持久化逻辑 deadline，物理 alarm 始终设置为两者的最早值；任一流程完成只清除自己的 deadline 并重新计算。Turn submit 与 running cancel 先成功持久 arm 再提交队列或取消 intent。只有首次原子建立取消 fence 的事务可以调用 `runtime.cancel`，并发请求与重放只能 observe 同一 dispatch。[本地共享 alarm 证据](../evidence/runs/m2-shared-alarm-local-20260907/primary-review.json)验证组件与真实本地 Workerd SQLite alarm 语义；[Workspace 与产品 Runtime 接线证据](../evidence/runs/m2-workspace-runtime-wiring-local-20260907/primary-review.json)进一步验证 engine 已装入 WorkspaceAgent，路由按 provisioning → 权威状态重读 → Turn 的顺序执行，未 ready 的到期 Turn 延至未来，孤立 wake 不伪造 scope，全部路径最终重新合并物理 alarm。当前 Gateway 以 `M2_TURNS_ENABLED=false` 在 actor 解析与 journal 写入前拒绝新 Turn，staging 预检也锁定该值；[门禁证据](../evidence/runs/m2-turn-admission-gate-local-20260907/primary-review.json)证明关闭时不会创建永久排队项。该门禁已经部署为 staging 版本 `beeb20f0-6346-405e-88ea-632ea87863d8`，[云记录](../evidence/runs/m2-turn-admission-gate-staging-20260907/deployment.json)确认没有 Container 构建或滚动。新增 runtime binding 和接线尚未部署。

## 持久化

Cloudflare Sandbox `createBackup()` 可以加速容器休眠后的目录恢复，但 backup handle 有 TTL，生产恢复采用随容器消失的只读 lower layer 加可写 overlay。本产品不把它当作长期 Revision 或唯一数据源。

可信保存顺序固定为：WorkspaceAgent 在 claim 事务内冻结最新 workspace head 与当前 Session head → Runtime 按该基线恢复 → 停止模型与项目写者并确认 fence → 从项目 VM 冻结并读取文件 → 从可信 Pi VM 导出静止 Session → 写入产品 R2 的不可变内容对象与 schema v2 manifest 并回读摘要 → WorkspaceAgent 提交新的两个 head、Revision 指针与 Turn 终态。每个声明的基线 manifest 及其 files/Session blob 都必须在新 snapshot 开始前验证摘要、scope、generation 和 Session 归属；项目或 Pi 输出不能选择父版本。[本地基线版本链证据](../evidence/runs/m2-turn-base-lineage-local-20260907/primary-review.json)覆盖这条控制链及持久 head 篡改拒绝。Sandbox backup 只能作为可丢弃缓存；恢复后仍从产品 Revision 校验文件与 Session。

项目文件 blob 使用规范 USTAR：只含规则文件和目录，路径必须是 NFC UTF-8 的规范相对路径并排除 `.riffology`；uid/gid 固定为 0、owner 名为空、mtime 为 0，模式限制为 0600/0644/0700/0755。单文件最多 32 MiB、归档最多 56 MiB、条目最多 4,096，R2 reader 对项目归档与 Pi Session 的实际回读字节再施加 64 MiB 聚合上限。恢复器以完整 Turn identity 派生 52 位 token，在 root-only archive 目录保留输入、锁和成功 marker。它先在 `/workspace/.riffology` 提取，再重新冻结并逐字节比较；只有校验成功才清理并安装顶层目录项。`/workspace` 在 Sandbox 中是独立挂载点，不能跨挂载 rename 整个目录，因此这里的安全边界是“Pi 启动前完成或失败”，不是对运行中进程可见的整目录原子切换。失败不会启动 Pi，下一次恢复以保留输入重建；成功后同 token 重放返回原收据且不覆盖本回合后续修改。[本地归档证据](../evidence/runs/m2-workspace-archive-local-20260907/primary-review.json)连续两次验证源 Sandbox 销毁后由另一个派生 actor 恢复相同内容与摘要。

## 现有组件边界

M1 `ProjectRuntime`、`RuntimeCore` 和 `Dockerfile.cloud` 只负责 blank Workspace 初始化、固定初始 Checkpoint 与停止确认。它们保持原职责，不作为 Pi Turn executor。M2 新 Runtime 使用独立状态、镜像和 Sandbox actor。`services/turn-runtime/` 的产品编排 core 已建立独立 SQLite row、执行与取消 fence、Checkpoint port、包含 Pi `sessionId` 的完整 actor identity，以及由 WorkspaceAgent 冻结的 workspace/Session 双基线；它只依赖 M2 Turn contract，不导入 M1 Runtime 或 M0 Pi probe。独立 `ProductTurnRuntime` SQLite Durable Object 和 Workspace 侧 client 都从完整 identity 派生 actor，错误 actor 在 release 或存储前拒绝；生产 release factory 只有在 `M2_TURNS_ENABLED` 精确为 `true` 且 R2、Project Sandbox、Trusted Pi Sandbox 绑定齐全时才组装，actor 在真正执行时才解析。R2 adapter 物化并回读校验文件归档、Pi Session、身份 manifest 和每个基线对象；Project Workspace lifecycle 在 Pi 启动前把已校验归档恢复到派生 Project actor，终止后从同一 actor 冻结。Workspace TurnJournal 仍是 `saved` 的权威记录。ProductTurnRuntime 的物化时间可早于 WorkspaceAgent 随后的 checkpointing 记录；Journal 以执行证据校验物化时间，以本地事务提交时间记录终态和事件。checkpoint commit 或首次 observe 的响应都未知时，Runtime 保留一次性 materialization fence，Workspace Turn 保持活动 `checkpointing` 并由 alarm 重查同一 receipt；确认晚到后才提交 `saved`，不会再次调用 commit。确定损坏的恢复基线不能产生合法新 Revision，仍直接失败并释放队列。该组装已通过本地四种终态、跨身份拒绝与无 eager allocation 测试；provider 关闭条件下的真实双 Turn、R2 合并保存、Sandbox 销毁后恢复和损坏基线拒绝也已通过本地验收。云容器、真实付费 provider 与错误身份故障注入仍待验收。

M2 Trusted Pi 使用仓库根目录的独立 Dockerfile、依赖锁和固定 turn host。根目录位置让 Wrangler 以仓库为构建上下文，只复制受审查的 runtime 与 Trusted Pi 文件；源码清单也显式包含该 Dockerfile。镜像锁定 Pi Coding Agent 与其运行时导入的 Pi Server 0.85.0，固定 `/usr/local/bin/node`，直接启动真实脚本路径；活动 release 位于 Trusted Pi 模块目录，使相对 transport 导入保持封装一致。control 只含平台身份、用户消息和输入 Session 摘要；固定模型、system prompt、Simulation Skill、七个远程工具与 transport 只能来自镜像内受审查的 release 模块。候选 transport 给 Pi SDK 一个不可外传的占位字符串以满足接口，实际请求头由 Worker 重建；Trusted Pi 不持有供应商凭据、capability key 或服务 binding。模型输入当前只接受文本，并固定 `stream=true`、`store=false` 与最大输出。平台自有 transport 在 provider adapter 解析前记录所有 HTTP 响应，保证非 2xx 也产生明确状态事件。host 通过 `createControlledPiSession` 恢复/导出 Session，先原子写输出 Session，再写 terminal 结果。terminal 文件不等于原生停止证明；只有 Sandbox supervisor 观察同一 process ID 已退出且 exit code 为 0 才可向 Product Runtime 签发 fenced stop receipt，进程登记缺失保持 `unknown`。更新后的 Trusted Pi `linux/amd64` 验证镜像已完成真实本地 Turn，但产品活动入口仍指向失败关闭 release；尚未推送或部署。

M0 的双 Sandbox、受控 Pi、模型代理和文件探针是可迁移原语；其固定 run、诊断 token、workers.dev 地址和测试入口不得进入 M2 产品配置。

当前 `services/sandbox/` 已冻结 actor ID、class 与出站策略候选，并把真实 `NativeProjectEffectPort` 和 SQLite supervisor 装入本地 `ProjectToolSandbox`；尚未加入 staging binding 或创建 M2 Container application。Project Sandbox 的文件 RPC 在进入 effect 前验证短期 HMAC capability，绑定具名 actor、scope、Turn、dispatch、command、effect、command digest 与 expiry；密钥只留在 Worker/DO 环境，`envVars={}` 不把它传给项目容器。`ToolBridgeAgent` 持有 SQLite Tool Ledger，只有 `dispatch()` 返回一次性授权后才由平台适配层根据已校验 scope 派生 Project actor 并签发 capability；终态或 unknown 重入只进入回放/observe。内部 `/v1/tool` 由 named Worker service entrypoint 承载，公网/default handler 不导出该路由。Trusted Pi outbound 移除来路身份头后，以 Worker-only HMAC 绑定容器 ID、时间与正文摘要；服务端再从 command scope、Turn、dispatch 派生应有 Trusted Pi DO ID 和 Tool Bridge actor，错误 scope 在账本前拒绝。生产 WorkspaceAgent 仍须成为命令 scope、Turn、dispatch 与 generation 的唯一来源。空 `envVars` 本身仍不构成“运行环境无秘密”的证据；产品验收必须在两个真实 VM 内检查环境、文件、进程、localhost 和网络，并拒绝敏感变量或错误镜像内容。

Model Proxy 使用两层独立授权。平台在 Trusted Pi outbound 边界签发短期 capability，固定完整 Turn identity、提交 actor 与 auth version、派生 Trusted Pi actor、预算策略版本、provider/model 和单次 Token 上限；Sandbox outbound 的 Worker-only MAC 再绑定实际 container ID、30 秒请求时间、capability 摘要和正文摘要。私有 handler 通过 Sandbox namespace 把 capability 中的 actor name 映射到实际 DO ID，随后才调用 Tenant 范围的 SQLite `TenantModelBudget`。预算账本以不含 Runtime `dispatchId` 的稳定 Turn key 聚合，恢复不会获得新额度；每个 call ID 只有一次 durable dispatch 授权，未知结果保留全部 Token 上界并禁止自动重发。固定 OpenCode Go Responses adapter 只访问 `https://opencode.ai/zen/go/v1/responses`，重建认证和模型字段，限量缓冲 SSE，验证唯一 completed/incomplete 终态、provider request ID 与 usage 后才结算和返回原始字节。该 authority 只管理调用次数和 Token，不管理价格、现金余额或付款；后者仍属于未来 `TenantBilling`。`ModelProxyService` 还受独立 `M2_MODEL_PROVIDER_ENABLED` 精确开关控制，默认在预算预留前返回 503。[本地契约证据](../evidence/runs/m2-model-budget-local-20260907/primary-review.json)不包含真实模型或云 VM；[Workerd RPC 证据](../evidence/runs/m2-model-budget-workerd-local-20260907/primary-review.json)进一步覆盖真实 SQLite DO、跨 Tenant actor、进程重启与策略冲突；[发布链证据](../evidence/runs/m2-product-release-chain-local-20260907/primary-review.json)覆盖固定 provider、Pi transport、能力票据、预算组合链和默认关闭拓扑。

`services/project-tools/file_service.py` 以固定 root fd、逐段 `O_NOFOLLOW` 和同目录原子替换抵抗路径逃逸；原子替换后的异常明确升级为 unknown。effect envelope 只向 helper 发送文件参数，平台身份与 receipt 由可信侧持有；SQLite supervisor 在 native start 前持久化一次性 fence，并能在丢响应后以 retained command digest 恢复 terminal。[本地 Workerd + Sandbox SDK RPC](../evidence/runs/m2-project-sandbox-rpc-20260907/primary-review.json)验证固定 wrapper、真实容器写入/读回、actor capability 的篡改与错误 actor 拒绝，以及重复 effect 摘要冲突；[本地 Durable Tool Bridge](../evidence/runs/m2-tool-bridge-local-20260907/primary-review.json)进一步验证真实 SQLite Ledger 授权、双 actor 派生、终态回放和改写 payload 拒绝。[Trusted Pi 内部 HTTP 链路](../evidence/runs/m2-trusted-tool-http-local-20260907/primary-review.json)在锁定的 Sandbox 0.12.9 上验证 outbound `context.containerId = ctx.id.toString()` 与具名 Sandbox DO ID 的一致性，并连续两次完成真实 Trusted Pi 容器到项目文件的链路；SDK 升级时必须重新证明该身份契约。Trusted Pi 候选现在只暴露 `project_read/read_page/write/edit/list/search/bash` 七个闭合 schema 工具，每个工具调用从受控 Session scope 与完整 Runtime identity 派生命令 ID、deadline 和 Tool Bridge 请求，返回值必须是身份、命令、effect 与时间顺序一致的有界终态。

超过 16 KiB 的 read/list/search 终态由平台 `ToolArtifactStore` 单独持久化。Project Sandbox 不持有该 DO 或 R2 binding；Tool Bridge 只提交完整 effect identity 与规范 JSON 字节。ArtifactStore 独占 `tool-artifacts/` 前缀，RevisionStore 继续独占 `turn-blobs/` 与 Revision manifest；两者不能扫描或删除对方对象。ArtifactStore 在 R2 await 前持久化 reservation，DO 重建把遗留 reservation 降为 unknown；相同 identity 的内容变更冲突，只有原 descriptor 可 reconcile。公开 receipt 不含 object key，WorkspaceAgent 复核自身 actor 和 scope，Gateway 用 Catalog 的当前所有权保护 artifact ID 读取，并在响应前再次复核字节数和 SHA-256。Trusted Pi host 不复制工具完整结果，只从严格 artifact 结构提取 receipt；Product Runtime 复核后将 receipt 投影到 `tool.completed`，用户端再以当前 Workspace 和白名单 artifact ID 生成只读链接。`project_read_page` 使用字节 offset、每页上限和首段 SHA 锁定同一文件版本，JSON 转义过多时自动缩页。[分页、Artifact 与 UI 本地证据](../evidence/runs/m2-read-page-artifact-ui-local-20260907/primary-review.json)覆盖真实 Project Sandbox 分页、不可变 R2 单对象重放、host/runtime 事件映射与浏览器安全链接。ArtifactStore 现拥有独立引用表：artifact reservation 与初始 `tool_effect` 引用在同一事务创建，旧行在对象激活时由规范 identity 严格回填；Workspace Dispatcher 在写入 `tool.completed` 前先幂等 retain 对应 `turn_event`，scope、Turn、dispatch 或 receipt 不一致时失败关闭。该顺序在 journal 失败时可能保守泄漏，但不会误删。当前 WorkspaceAgent 私有接口可在原 Turn 已终止且事件及幂等回执均已退出 journal 后，幂等释放对应 turn_event 引用；自动调度已由 ArtifactStore 独立 alarm 提供每页 50 条、固定上界和持久游标的本地候选，tool_effect 释放尚未实现，Artifact 删除与 GC 均未实现，因此不得删除 `tool-artifacts/` 对象；发布前还必须从 Tool Ledger 终态和 journal 压缩建立可恢复 release 生命周期，再实现保留期与分阶段失败关闭 GC。[Artifact 引用权威证据](../evidence/runs/m2-artifact-reference-wiring-local-20260907113144206/primary-review.json)覆盖旧行升级、引用幂等、跨租户拒绝和 Workerd 端到端装配。仍未完成 Artifact 云接线、云 VM、跨租户并发、临时文件回收或完整恢复验收。

## 验收要求

- 项目进程无法读取可信 Pi 文件、Session、模型 capability 或 Worker secret；可信 Pi 不能绕过 Tool Bridge 直接访问项目文件。
- 旧 generation、错误 dispatch、重复 command、过期 deadline 和任意 Sandbox ID 均在外部效果前拒绝。
- cancel/transport unknown 后只观察同一身份，不重放未知模型、bash、write 或 edit。
- Sandbox 销毁后以产品 R2 Revision 恢复相同文件和 Session 摘要；仅有临时 backup handle 不算通过。
- 两租户并行运行时文件、进程、localhost、事件、Checkpoint 和预算互不可见。

依据：Cloudflare 当前说明不同 Sandbox 使用独立 VM，而同一 Sandbox 内所有进程共享文件、进程可见性和 localhost；供应商凭据应由 Worker 出站处理器保留。[Security model](https://developers.cloudflare.com/sandbox/concepts/security/)

目录备份在生产使用 FUSE overlay，容器重启或休眠后 mount 消失，必须再次恢复；handle 可持久化但受 TTL 约束。[Directory backups](https://developers.cloudflare.com/sandbox/concepts/backup-restore/) [Backup API](https://developers.cloudflare.com/sandbox/api/backups/)
