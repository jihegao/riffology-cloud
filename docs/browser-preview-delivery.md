# Browser Preview G2 client and static delivery

The local model panel is `services/web/browser-preview.js`, mounted before the existing server Preview. It reads the authenticated workspace view and canonical private package bytes through GET. Run locally invokes the isolated browser runtime; playback uses its shared Canvas/lane renderer. Neither playback nor restoration invokes a server Run. Verify explicitly captures the displayed saved revision, package identity, resolved parameters and uint32 seed and persists one idempotency key before submitting. A lost response preserves that captured request for explicit retry; restoration reads the existing key through GET and clears it only when the server echoes the same capture with an accepted experiment.

Parameters are session-scoped by tenant, project and immutable package identity. Results remain in bounded runtime/player memory and are released on navigation. A head change shows the old saved identity until a fully validated replacement package is available. A standalone link `#/workspace/:project/browser-preview/:revision/:packageIdentity` enters only after the existing login/project authorization flow and does not restore server Preview or acquire a runtime ticket. OAuth preserves only a validated local hash route.

`execution/materialize.mjs` reads the committed G1 profiles and host receipt plus previously prepared `.local/browser-preview/assets` and immutable delivery bundles. Run `node services/browser-preview/runtime/prepare-assets.mjs` then `node services/browser-preview/execution/materialize.mjs`. Default mode rejects static-index drift. `--update-index` is an explicit review operation; `--retain /absolute/prior-static-index.json` keeps older approved URLs only if their original bytes are still present and match the receipt. Do not silently overwrite or synthesize missing retained delivery. Binary assets remain ignored. The standalone renderer is bundled with the exact pinned receipt compiler/options to avoid cross-directory relative imports.

The trusted app exposes only generated app URLs `/browser-preview-assets/<sha256>/<path>`. `serveBrowserPreviewAppAsset(request, binding)` verifies length and SHA-256 on every GET/HEAD, including the second browser import request. The Gateway owner composes `services/web` with `.local/browser-preview/app-assets` into its actual ASSETS directory; the helper does not proxy caller headers or arbitrary URLs. The client additionally verifies host/renderer module hashes before importing them.

`execution/index.ts` and `infra/wrangler.browser-execution.jsonc` are the separate static-only Worker. Its binding contains only three immutable frame/worker URLs per retained runtime. Requests with unknown paths, queries, Cookie, Authorization or non-GET/HEAD methods are denied; there are no project/package/API routes and no network asset broker. Every response is checked against the generated receipt and removes Set-Cookie. Production requires exact HTTPS APP_ORIGIN/EXECUTION_ORIGIN on different sites and a fixed frame-ancestors APP_ORIGIN. Empty production vars fail closed until an operator supplies audited domains; no production domain was selected or deployed. The hostname comparison conservatively rejects a shared last two labels, so public-suffix edge cases can be rejected rather than granted. An explicit localhost HTTP environment exists for local acceptance only.

The Worker JavaScript CSP has `script-src 'unsafe-eval' 'wasm-unsafe-eval'` with no URL sources, `connect-src 'none'`, `worker-src 'none'`. The eval permission comes from the pinned Pyodide dynamic-library loader documented in the G1 execution contract. The trusted frame allows self script/Worker bootstrap and fixed app ancestry; generated Python is confined to the Worker. No cloud credentials enter the runtime.

Validation: `node --test tests/m3/browser-preview-panel.test.mjs` has four browser UI fixture cases, explicitly using a fake runtime to test client transitions rather than claiming isolation. `node --test services/browser-preview/execution/execution.test.ts` has three receipt/CSP/denial tests backed by real materialized binary files. Missing files fail these tests and never count as a skip or passed runtime. Full G2 acceptance additionally requires the separate real Gateway/RevisionStore/R2/D1 driver and G1 real Pyodide evidence. No deployment or LLM generation is part of these checks.
