## Observed execution isolation gap

Workerd outbound rejection is insufficient as the translated project process network fence. Inside the actual SDK container, a controlled UID 10001 CPython child connects to both a controlled root loopback TCP listener and a root Unix socket listener, and both listeners receive `project-arrival`. `g3-network-boundary-probe.py` records the actual child UID, connection outcomes and server arrivals. It intentionally does not install or claim the native project fence.

The unchanged production native fence fails closed in local amd64 translation with seccomp load error -125. Adding its existing translated-platform marker while relying only on Workerd egress would allow the observed root connections and cannot sign G3 isolation. Applying the G1 whole-container deny-all socket policy would also block the root Sandbox SDK server needed by this chain. The current Miniflare Docker schema exposes socket and proxy image configuration but no caller-supplied per-container security policy. A real native execution environment or a verified project-specific kernel policy is required before successful native execution can complete the G3 gate. No fixture runtime will substitute for it.

## Complete driver contract

The final driver will use actual Gateway cookie and ACL handling, Workspace journal session/submit/claim/checkpoint operations, RevisionStore commit and actual R2 bytes for the canonical five-file fixtures. Deterministic fixture production is explicitly separate from ordinary Agent generation. Project initialization must use actual provisioning; it must not seed ready initialization or catalog model rows.

For each canonical Queue/Mesa source, the gate must persist a checkpoint, restart Workerd with no browser page, and observe the shared alarm produce a compatible ready private package. GET package bytes must pass the immutable archive/profile/source identity chain. The production Browser worker must run seed 7 and the fixed G1 parameters; the local window must have no new native/Pi execution, Experiment or Run. Verification must capture the exact old revision/package/input, remain idempotent after a newer save, reject changed input under the same key and reject revoked/cross-tenant access. Actual SimulationHost and native execution must persist Run receipts and bounded artifacts to real R2 and produce an actual Gateway export with real Python replay. HTTP/R2 shims, direct ready-row inserts and fake native receipts do not meet this contract.

Publication review is read-only: `publicationContent` preserves the accepted `model/` and `app/` files with per-file hashes, so the five canonical source paths fit the existing whitelist. Browser runtime assets/profile inventory remain trusted platform assets rather than arbitrary publication source files. Initial copied projects lacking a saved revision are a separately recorded product compatibility gap; the driver will not work around it by inserting a model or manufacturing a saved receipt.

## Test-only native ARM64 bridge

A bounded diagnostic solved the SDK communication conflict without changing production code. `python3 scripts/m3/g3-build-arm64-helper.py --image` uses the installed clang assembler to produce a freestanding static Linux ARM64 ELF, rejects every relocation and constructs a fixed single-load executable. Source, binary, assembler version, original image identity and derived test image identity are written to `.local/g3-native-helper/{build,image}.json`. No system compiler/package is installed; a failed public compiler-container download is retained as a separate diagnostic.

The helper requires actual project UID 10001, installs an ARM64 host-kernel seccomp filter, checks actual kernel `PR_GET_NO_NEW_PRIVS=1` and raw native io_uring setup/enter/register syscalls all return EPERM, then execs the original translated CPython. The image `riffology-g3-native-bridge:local` wraps only its interpreter entry paths; root SDK/monitor execution uses original CPython, while project UID receives the kernel helper. It is labeled `g3-arm64-kernel-bridge-not-production` and includes the existing translated-platform marker only with this bridge. No production runner, execution profile or production Dockerfile changes.

`G3_NATIVE_BRIDGE=1 G3_SIMULATION_IMAGE=riffology-g3-native-bridge:local node --experimental-strip-types scripts/m3/g3-sandbox-connectivity.mjs` passed: real SDK remains 200 before/after the probe, actual child UID/GID are 10001 with no supplementary groups and NoNewPrivs is 1; loopback/Unix/external TCP and UDP connect plus UDP sendto return EPERM; both controlled root listeners have zero arrivals. Guest ctypes io_uring returns ENOSYS from translation, separately from the helper's verified raw native EPERM. The guest address-space limit remains unlimited, so G4 native AS inheritance remains unproven. This diagnostic is a separately identified local bridge image, not the production x86_64 image.

Before G3 native acceptance, both Mesa's explicit profile interpreter and Queue's historical empty-lock `sys.executable` route must be verified through actual SimulationHost execution. The initial shell wrapper may give the root monitor an original executable name that bypasses the Queue bridge; successful Mesa diagnostics do not close that path. The full driver will record actual child fence behavior for both routes and will not accept an unverified bypass.

The Queue bypass is now addressed solely in the separately named test image `riffology-g3-native-bridge-queue:local`. Its root-owned system-3.11 `sitecustomize.py` assigns `/usr/local/bin/python3` to `sys.executable` only for UID 0, ensuring the unchanged legacy empty-lock monitor chooses the kernel bridge. Project UID does not change its executable and receives no PYTHONPATH. The image builder records this hook's SHA along with helper/source/image provenance; no production profile identity is changed.

`node --experimental-strip-types scripts/m3/g3-native-profile-probe.mjs` passed both actual SDK/production SimulationNative paths: chunk upload, digest-checked control, start/observe and fenced seal.
