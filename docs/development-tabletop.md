## 1. 推演方法与证据边界

本次沿用户的真实目标，依次推演“复制官方机场 Starter → Pi 修改模型 → 保存版本 → 共享观察 → 批量实验 → 中断恢复 → 消费结算 → 发布更新”。每一步先提出首次实现容易采用的做法及其可能失效的位置，再代入修正后的设计检查状态能否闭合。

这是桌面推演，不是一次实际部署或故障测试。本仓库的 UI 原型采用本地示例数据；`ui/app.js` 使用浏览器存储，`ui/workspace.js` 使用演示回复、版本号和实验计数，`ui/user-pages.js` 的充值不连接支付服务。这些代码能支持交互评审，不能证明多租户隔离、Pi 执行、持久化、供应商消费或支付结算已实现。后续开发已有部分本地探针和真实供应商记录，单独见[开发执行状态](development-status.md)；它们不使下文的推演案例自动成为已执行测试。

“首次实现风险”表示条件性预测，不表示已经发生事故。“修正后预期”表示工程实现和测试必须达到的结果；验证证据栏规定验收材料，实际是否已采集以关联运行记录为准。Cloudflare、Pi SDK 及支付渠道的具体能力还须由 M0 技术验证和后续测试确认，不能从平台名称推断应用保证。

### 1.1 推演角色与输入

| 对象 | 本次假设 |
|---|---|
| 用户甲、乙 | 两个独立登录身份，各自拥有个人 Tenant `tenant_a`、`tenant_b`；名称与标识均为推演符号 |
| 用户甲项目 | `project_a1` 和 `project_a2`，归同一 Tenant，共享预算但不共享可写目录 |
| 用户乙项目 | `project_b1`，归另一 Tenant；不能访问甲的任何私有对象 |
| 官方 Starter | 固定版本 `airport-ground@1.0.0` 与内容摘要 `D0`；示意版本，不代表真实发布包 |
| 建模要求 | 飞机到达、等待、保障、离场；比较 4 组与 6 组保障资源 |
| 实验 | 2 个参数组合，各 10 次；执行前保存 20 个子任务、参数与互异种子；示例回放种子 `20260101` 是其中一项，具体数值没有平台级约束 |
| 运行输入 | 已提交 Revision、依赖锁摘要、runtime 镜像摘要；不用“当前最新文件”代替输入版本 |
| 账单条件 | 单 Tenant、单结算币种；示例预留使用抽象整数金额单位，不构成平台定价 |

### 1.2 阶段与阻断等级

阶段沿用：M0 技术验证，M1 身份与隔离，M2 Pi / 持久回合 / 文件恢复，M3 Browser 与 Starter，M4 独立 Run 与实验，M5 综合可靠性验收，C1 官方目录，C2 付费测试，C3 付费灰度。

| 等级 | 含义 | 发布处理 |
|---|---|---|
| P0 | 跨租户访问、凭据或控制面暴露、已确认数据丢失、重复副作用、越过用户授权扣费等硬边界失守 | 阻断引入该能力的阶段；在实际隔离环境验证并复测通过后才能开放 |
| P1 | 关键旅程无法完成、状态或结果误报、无法恢复、成本失控或无处置出口 | 阻断该能力上线；仅可在明确关闭该能力且基础范围仍满足的情况下继续其他阶段 |
| P2 | 可恢复且不损害权限、数据、资金的体验或运维缺口 | 记录负责人、补齐期限和上线影响，不用它豁免核心验收 |

## 2. 先固定权威状态和产品边界

| 内容 | 权威归属 | Pi 在项目内的权限 |
|---|---|---|
| 登录、Tenant / Project 归属、ACL、管理权限 | Gateway 与身份目录 | 只能在当前授权范围内发起操作，不能编写或覆盖平台授权 |
| Session、Turn、事件序号、当前保存指针、Run 生命周期 | WorkspaceAgent | 提交工具请求；不能伪造保存、完成、停止或授权收据 |
| 模型、模型应用、参数含义、实验配置、分析说明 | 项目代码与配置，由 Revision 固定 | 可生成和修改；官方复制内容保留来源，不全部称为 Agent 生成 |
| Preview 服务的启动、停止、代理访问和观察授权 | 平台服务管理与 Browser 插件 | 可通过工具请求平台托管；不能自行发布免鉴权地址 |
| 仿真时钟、保障资源、队列与模型指标 | 项目 Preview 后端；属于项目应用 | 可构建、修改并暴露受约束的模型操作 |
| 结果是否已保存、实际完成子任务数 | Run 的持久化收据 | 产出结果；摘要不能替代结果校验和收据 |
| 余额、预留、用量分类、结算与退款 | TenantBilling 与服务端支付凭据 | 只能使用获准资源，不能提交可信用量或更改账本 |
| 已发布官方版本及平台 runtime / Skill | 平台发布流程 | 项目文件不得自动变为平台扩展、代码或发布包 |

因此，模型滑块和机场画面属于项目应用；Browser 外层工具栏属于平台；“暂停仿真”“停止 Preview 服务”“取消 Agent 回合”“停止实验”是四项独立操作。项目代码直接调用的声明、页面文字或日志都不是平台权威事件。

## 3. 十六步开发旅程推演

### 3.0 先模拟工程团队怎样完成开发与交付

以下 E01–E12 是工程流程推演，T01–T16 是紧随其后的产品与故障推演。假设团队从当前设计和本地原型开工，每一行先遇到一个条件性问题，再决定下一步；没有把这些问题写成已经发生的事故。

| 步骤 / 阶段 | 模拟开发动作与遇到的问题 | 应对与下一步 | 交接产物 / 责任 |
|---|---|---|---|
| E01 / M0 | 拆工作包时，前端把机场图和运行状态都分给平台 Shell | 按固定边界提示逐项归属；模型应用与平台通用状态分别定义；关闭 R01 的错误实现路径 | 边界表、API / 事件样例；主控 + F + B2 |
| E02 / M0 | 开始联调才发现云资源能力、域名或测试预算未就绪 | 先做资源 preflight，记录实际可用性和责任人；继续本地契约、夹具与构建，云门禁保持未通过 | 环境台账、缺口和依赖；O + 主控 |
| E03 / M0 | 默认 SDK 能启动，但项目扩展或内部控制 API 使信任边界不成立 | 按 ADR 分离可信 Pi 与项目执行域，限定资源加载和工具桥；在真实环境证伪 R04 / R05 / R09 | 版本锁、ADR、十项 G0 报告；B1 + B2 + Q |
| E04 / M1 | 两端页面并行完成，服务接口字段不同，管理员角色又被当成全权限 | 先冻结归属链与契约；服务端先拒绝越权；管理员只接运维数据；不得靠隐藏按钮修复 R02 | 身份 / 项目纵向 PR、双用户拒绝矩阵；B1 + F |
| E05 / M2 | 第一个 Agent 回合可改文件，但保存失败后 UI 仍显示完成 | 先交付可恢复文件提交，再接持久 Turn 与真实 Pi；分别处理执行、保存和未知副作用，关闭 R06–R08 | 初次可写回合、提交窗口故障证据；B1 + B2 + F |
| E06 / M3 | 机场 Preview 可看，换第二应用却要改平台；Observer 访问使状态变化 | 以第二应用真实运行检验通用契约；区分平台观察权限与项目领域副作用，验证观察接口；处理 R01 / R09 / R10 | 两项目、双上下文和独立停止证据；B2 + F + Q |
| E07 / M4 | 单次仿真通过，扩成 20 次后结果重名，取消留下子进程 | 先固定样本 ID / 种子 / 输入 Revision，再逐样本确认持久结果；用进程归属和退出确认处理 R11 / R12 | 20 样本计划与收据、导出和取消证据；B2 + B1 |
| E08 / M5 | 子任务都报告通过，合并后的构建却不对应测试版本 | 主控复核最终源码与锁文件，按影响重跑集成；从一次构建生成不可变发布清单，禁止把不同版本证据拼接验收 | 候选摘要、测试和风险关联、G5 结论；主控 + Q |
| E09 / staging | 部署命令成功，但 runtime 镜像或存量 Workspace 恢复失败 | 分别核对 Worker、镜像、实例和公网流程；停发新工作，按维护 / 排空方案恢复；复验 R08 / R13 | D01–D10 部署与回退记录；O + B1 + B2 + Q |
| E10 / 邀请生产 | 内部流程正常，但持续 Preview、Observer 和存储超过预算 | 同一已验收产物逐批推广，按真实样本与休眠恢复观察；配额和保存余量控制 R17；不足则延长观察 | D11 邀请名单、成本与告警记录；P + O |
| E11 / C1–C2 | 官方包验证后被改动，支付测试出现重复回调和未知用量 | 摘要变化使验证失效；先做不可变发布，再实现原子预留、追加账本和限时对账，验证 R14–R18 | GC1 / GC2、支付测试与余额守恒；B1 + B2 + Q |
| E12 / C3 | 测试环境通过，准备直接向全部用户收费 | 先冻结价目与政策，完成小额真实支付、消费、退款和恢复；证据齐全后小范围放量 | GC3、运营手册、对账与值守；P + O + 主控 |

每一步返回到对应工作包修正并重测，不用后续页面完成数量抵消前置门禁失败。主控负责集成与质量结论，子任务实现者负责可复查产物；产品内 Pi 仅构建项目内容，不承担这套平台开发部署权限。

### T01：先接工作台，再决定机场功能放在哪里

- **触发与首次实现风险：** 开发者复用原型，将机场参数、进程控制、模型状态和保存标记都保存在同一前端对象。当前原型的 `paused` 同时影响模型动画和 Runs 中的 Preview 展示，足以提示这种边界混用风险；它并不表示服务端已经存在此缺陷。
- **修正后再推演：** 平台 Shell 只提供会话、文件、运行、插件宿主与授权；机场应用来自 Starter 的 `app/`，模型来自 `model/`。嵌入区域标明项目应用及来源版本，平台工具栏标明托管状态；分别调用模型暂停与服务停止接口。
- **权威状态与用户表现：** 前端显示服务端返回的 `service_run_id`、Revision、Preview 状态；模型后端返回仿真状态。关闭 Panel 后服务可继续，暂停模型后服务仍就绪，停止服务后显示停止状态。
- **处置与验证证据：** 输出边界接口表；用一个无机场知识的第二项目应用接入同一 Shell；对四种停止操作做状态变化矩阵，证明没有相互误触发。
- **阻断：** P1，M0 定契约，M3 验收；关联 R01。

### T02：甲、乙登录并交换项目标识

- **触发与首次实现风险：** UI 只过滤项目列表，API 信任 `active_tenant_id`；管理员登录后自动拥有项目内容。甲粘贴乙的 Workspace、Session 或 Artifact 标识时，可能绕过页面过滤。
- **修正后再推演：** 每个入口验证 User → Membership → Project → Workspace → 子对象的归属链；对象名由已授权上下文派生。管理员只获得明确的运维操作，本计划不开放运维身份读取用户内容。长连接处理身份到期和撤销。
- **权威状态与用户表现：** 身份目录和 ACL 决定权限，客户端选择不改变归属。拒绝请求不返回私有对象内容；正常用户仍能打开自己的项目。
- **处置与验证证据：** 甲乙双会话覆盖文件、事件、日志、Run、Artifact、插件操作、WebSocket 升级与撤销；保留脱敏请求、响应和拒绝审计。管理员运维与内容访问分别测试。
- **阻断：** P0，M1 首次实现就验收，M5 全面复测；关联 R02。

### T03：两人从同一 Starter 建独立项目

- **触发与首次实现风险：** 官方包直接作为共享可写目录挂载；创建请求重试生成两个项目；复制一半便显示“就绪”。甲修改模型后，乙或官方目录可能跟着变化。
- **修正后再推演：** 校验固定版本的发布状态、摘要与许可；按用户幂等键创建 Project / Workspace；复制到各自可写目录并提交初始 Checkpoint 后才就绪。复制中断保留 `provisioning` 及可重试步骤，不重复建项目。
- **权威状态与用户表现：** 官方 `D0` 不变，甲乙分别拥有初始 Revision 与来源记录。甲的编辑只产生甲的版本；创建失败页显示可恢复阶段，不出现可运行的半成品。
- **处置与验证证据：** 同一请求重复提交一次创建；并行修改后比较官方、甲、乙的文件摘要；在复制途中中断并恢复；证明已撤回版本拒绝新复制。
- **阻断：** P0（共享写入）/ P1（初始化状态），M1–M2；目录治理在 C1；关联 R03。

### T04：Pi 首次启动并加载 Skill、工具和 Session

- **触发与首次实现风险：** 直接采用 SDK 默认项目资源发现；项目 `.pi` 扩展、Skill 或配置被自动加载。Pi、控制代理与项目 Shell 使用同一 UID，项目进程可能读取 Session、进程环境、控制能力或伪造收据。不同租户拥有独立 VM 不能解决同一个 Workspace 内的信任边界。
- **修正后再推演：** 只加载平台锁定的扩展、Skill 与配置清单，实际 SDK 加载选项在 M0 验证。按 ADR 0001 将可信 Pi / 控制代理与项目进程分离执行域，隔离可写挂载、控制端点和能力；权威 Session 包保存在可信域。项目输入只能成为建模资料，不能注册平台功能。供应商长期凭据只在平台代理使用；单独设置目录权限不足以证明隔离。
- **权威状态与用户表现：** 平台发布清单决定工具及 Skill，WorkspaceAgent 决定任务归属。项目中的自定义代码可以被编辑和执行，但不能扩大工具权限或改写平台事件。
- **处置与验证证据：** 云端技术验证投放项目扩展、配置、危险链接、探测 `/proc` / 进程环境和内部 Sandbox 控制 API 的测试夹具；验证不能读取可信域敏感材料、执行越权控制 RPC 或取得跨项目控制权，同时 20 次普通项目写操作成功。项目可接触自己的 SDK 控制 API 不代表取得平台权限，必须另外验证它不能扩大对象范围或伪造权威收据。分离拓扑未通过时继续修正 ADR 与实现并重测，不进入 M1 的真实执行接入。
- **阻断：** P0，M0 硬门槛并在 M2 复测；关联 R04、R05。

### T05：甲提交修改，同时上传数据并在另一 Session 发消息

- **触发与首次实现风险：** 长 HTTP 请求直接拥有 Pi 回合；上传、Shell 和另一个 Session 各自写文件。网络重试可能多派发一次，两个写入者可能使模型与参数互相覆盖。
- **修正后再推演：** WorkspaceAgent 在本地事务中持久化 Turn、请求摘要、队列及唤醒意图，再返回 `202 + turn_id`。同 Workspace 一个活动写入者，上传与命令进入同一调度边界；另一个 Session 的回合排队。派发带 Turn ID、generation 和租约，恢复先查询是否已执行。
- **权威状态与用户表现：** `queued / running` 来自持久 Turn，文件显示已保存视图或明确的工作中视图。甲能看到上传等待和第二回合排队，不会看到两个回合同时声称独占修改。
- **处置与验证证据：** 在接受后、派发前、确认后分别中断；重发同键同载荷应得到同 Turn，同键异载荷冲突。并行上传与 20 次创建、修改、删除、重命名操作的最终内容、Diff、队列和工具收据相互匹配。
- **阻断：** P0（重复副作用或写隔离失败），M2；关联 R05、R06。

### T06：供应商已接收请求，但用量与回答没有返回

- **触发与首次实现风险：** 遇到超时立即重试；没有 usage 就记零。首次请求可能仍在供应商运行，再调用会产生重复成本，Agent 也可能编造一个“修改完成”。
- **修正后再推演：** 记录每次模型请求的稳定 ID、派发事实和结果状态。明确未派发才可安全释放或重试；已派发结果未知则进入待核对，不能凭客户端断线重放。保存此前完成的文件操作；新继续操作与原未知请求分开记录。使用真实供应商先验证请求标识、错误和 usage 语义。
- **权威状态与用户表现：** Turn 显示 provider 错误或中断，文件保存状态独立。付费阶段用量标为待核对，既不猜金额也不把未知使用说成零；用户看到哪些工作已保存、哪些尚未确认。
- **处置与验证证据：** 受控测试代理分别模拟发送前失败、发送后断流、最后 usage 丢失和迟到响应；统计实际出站请求次数、用量状态、平台承担差额与是否产生虚假成功。真实供应商可用的核对渠道另行验证。
- **阻断：** P0（重复副作用或错误扣费）/ P1（无核对出口），M2；C2 验证账务，C3 前确定处理时限；关联 R07、R18。

### T07：Pi 已完成文件修改，保存中途失败

- **触发与首次实现风险：** 先广播“已保存”，再上传 R2；或文件内容上传后才发现删除清单、权限、Pi Session 对不上。容器随后失效可能丢掉已经承诺保存的内容。
- **修正后再推演：** 取得写锁并使写进程静止，形成文件清单、删除项与受保护 Session 包的一致检查点；先上传并验证不可变对象，再在 WorkspaceAgent 事务内提交指针、Revision 和事件。上传成功但指针失败的对象只形成可回收孤立对象，不能反向推进 UI。
- **权威状态与用户表现：** 当前提交指针仍是上一完整 Checkpoint，显示“执行已结束，保存失败”；热文件尽量保留并提供重试保存。只有指针事务完成后才出现新的“已保存”与 Diff。
- **处置与验证证据：** 在上传前、部分上传后、上传完成后、指针事务后分别中断；恢复时对文件内容、删除、必要权限、Session 包关联逐项校验。再做恢复后写入 / 重命名及超过临时备份 TTL 的恢复测试。
- **阻断：** P0，M2；关联 R08。

### T08：启动 Preview，乙拿到甲的地址并尝试直连

- **触发与首次实现风险：** 只鉴权首个 HTML；JS、API 或 WebSocket 直连原始地址；为解决 iframe Cookie 问题取消鉴权。项目代码也可能读取主站 Cookie、通过 XSS 影响主站或让 Observer 跳转到管理端点。
- **修正后再推演：** Preview 绑定已提交 Revision，在独立工作副本启动并健康检查。应用源与 Preview 源隔离，使用绑定主体、Workspace、实例、generation、范围及期限的授权；资源和 WebSocket 持续校验。源服务同时拒绝绕行，不能依赖原始 URL 随机性。Observer 有独立观察授权及导航限制，不持有用户写权限；领域无副作用另外按[项目观察契约](platform-project-boundary.md#53-项目仿真状态与平台观察投影)验证，不能只凭 GET 或截图推断。
- **权威状态与用户表现：** service Run 和 Browser 实例登记决定当前可访问服务；未经授权的乙、过期链接和被替换实例全部不可访问。用户在受支持浏览器内仍能加载页面、资源及实时状态。
- **处置与验证证据：** 覆盖原始端点、复制令牌、子资源、API、WebSocket、重定向、Cookie / Referer、主站 DOM 访问和顶层导航；保存各浏览器网络轨迹。无法同时满足隔离与嵌入体验时，先改变服务授权实现，再重测。
- **阻断：** P0，M0 验证可行性、M3 全链路验收；关联 R09。

### T09：用户把保障组从 4 改到 6，Agent 获取观察

- **触发与首次实现风险：** 滑块只改变用户浏览器内存，Observer 另开页面仍是 4 组；拿着旧截图声称看到当前状态；观察失败又使整回合变失败。
- **修正后再推演：** 模型后端持有 `simulation_state_id` 和递增状态序号；用户参数操作由模型后端确认。Observer 访问同一实例，证据带 Revision、generation、状态序号与时间。参数和时钟属于项目应用，不进入平台专属机场字段。观察失败只使该能力 degraded。
- **权威状态与用户表现：** 甲看到模型后端已确认的 6 组配置；Agent 准确引用某一状态及时间，不保证另一时刻的画面逐帧相同。替换实例后旧观察失效，模型结果和文件保存状态不被回滚。
- **处置与验证证据：** 两个独立浏览器上下文读取同一后端状态；按 4→6→4 操作检查序号；延迟观察、替换实例、阻断 Observer 后分别检查文案与事件。另在已暂停且没有其他写入者的 Starter 中验证观察前后状态不变，观察身份的领域写请求被拒绝。一般页面未验证领域副作用时明确标注。单纯同 URL 不能作为共享状态证据。
- **阻断：** P1，M3；关联 R10。

### T10：启动 20 样本实验，并继续修改下一版本模型

- **触发与首次实现风险：** 前端定时器累加 20/20；进程退出 0 就报全部成功；多个样本共用一个结果文件，或者实验读取正在变化的 `/workspace`。得到的结果可能重复、混版或缺样本。
- **修正后再推演：** 提交计划时固定 20 个子任务及互异种子、参数、输入 Revision、锁文件与 runtime 摘要；Run 从独立只读输入副本运行，写独立输出。每个结果经 schema、必要不变量、身份和摘要校验并持久化后才增加完成数。下一回合修改只产生新 Revision，不改变已有 Run 输入。
- **权威状态与用户表现：** 进度来自 `planned / completed / failed / cancelled` 子任务记录；活动任务可另显示 queued / running。若一项失败，应显示 19 完成、1 失败，整体默认不为 completed；下载包含已保存的真实样本。科学有效性仍需模型校准另证。
- **处置与验证证据：** 保存完整计划、20 个样本记录、日志和 Artifact manifest；故意缺失 / 重复 / 损坏一个结果应拒绝虚假完成。比较导出行数、唯一子任务数、种子和输入摘要；用固定种子与相同输入重跑核对结果。
- **阻断：** P1；若修改污染已固定输入则 P0，M4；关联 R11。

### T11：实验和回合执行时关闭页面，再从旧游标重连

- **触发与首次实现风险：** WebSocket 断开导致后台取消，重连又把历史消息重新提交；丢失的完成事件让 UI 一直显示 running。
- **修正后再推演：** Turn / Run 由服务端租约驱动，与页面连接独立。事件先持久化后广播；客户端用 `after_sequence` 补齐，超出保留窗口则获取权威快照和新游标。客户端展示去重，不通过回放再执行工具或扣费。
- **权威状态与用户表现：** WorkspaceAgent 的任务状态和单调事件序号有效；重连后只补状态。若后台已完成，直接恢复已完成及保存收据；若仍运行，接续实际进度。
- **处置与验证证据：** 分别在排队、流式回答、保存及实验 finalizing 时断开；重连同游标、过期游标并重复投递事件。对比任务 ID 数、出站调用数、账本条目和消息去重结果。
- **阻断：** P0（重复执行）/ P1（无法恢复观察），M2、M4，M5 组合验证；关联 R06。

### T12：用户取消回合，同时决定保留或停止独立实验

- **触发与首次实现风险：** 点击取消立即显示成功，后台 Shell 子进程仍写文件；或者全容器停止误杀已有实验和 Preview。暂停仿真又被误当作停止云端资源。
- **修正后再推演：** 取消先提交 `cancelling`，再终止目标 LLM 与短命工具进程组，确认退出、保存已完成修改后才进入 `cancelled`。独立 Run / service 有单独停止请求和登记；模型暂停只改变模型状态。无法确认退出时进入对账，旧租约不得继续写入或提交。
- **权威状态与用户表现：** UI 清楚展示正在取消、已取消、停止失败或待恢复；已保存文件和完成样本保留。取消 Agent 不会自动停止此前登记的独立实验；用户可再显式停止该实验。
- **处置与验证证据：** 用会派生子进程、延迟退出与持续写文件的测试工具验证进程组清理；分别执行四项停止，检查其他对象仍正常。记录取消耗时及最后一次写入 / 收据，预算结算只释放未发生部分。
- **阻断：** P0（幽灵写入）/ P1（错误控制对象），M2、M4；关联 R12。

### T13：保存后销毁 runtime，随后收到旧进程事件

- **触发与首次实现风险：** 新 runtime 沿用 PID、Preview URL 和租约；旧实例迟到完成事件把新状态覆盖；恢复时自动重跑执行结果未知的工具。
- **修正后再推演：** WorkspaceAgent 增加 `runtime_generation`，使旧租约、控制能力及服务授权失效；从最近已提交 Checkpoint 恢复文件与 Session 并验证摘要。所有回传及提交验证 generation 和当前执行租约；未完成工作对账为 interrupted，未知副作用不重放。
- **权威状态与用户表现：** 当前 generation 和提交指针决定可信状态；用户看到恢复至哪个保存点、哪些工作中断、哪些样本已保存。旧实例仅可作为故障线索，不能产生新业务收据。供应商已确认的原请求用量仍须核对，不能因 generation 失效抹去消费事实。用户显式继续产生可追溯的新操作。
- **处置与验证证据：** 真正销毁云 runtime 后恢复；注入旧 generation 的日志、完成、保存、服务及用量回传，验证业务拒绝与必要账务核对分离。比对文件哈希、Session 恢复关联、服务撤销和活跃进程清单。
- **阻断：** P0，M2，M5 组合验证；关联 R08、R13。

### T14：同 Tenant 两项目同时消费，支付通知重复到达

- **触发与首次实现风险：** 甲有 100 个可用金额单位，两 Workspace 同时各预留 70，分别读余额后都放行；取消或租约到期就释放已经派发的未知消费。重复支付通知可能再次增加余额。
- **修正后再推演：** TenantBilling 原子串行预留；此例只允许一个 70 预留成功，另一个获不足提示。调用授权绑定请求摘要、回合预算和价目表，Model Proxy 拒绝超出预留参数的调用。已派发未知状态保留待核对，由规定期限内的处置流程释放、结算或由平台承担；支付按服务端验证后的交易 ID 幂等入账。
- **权威状态与用户表现：** 余额净额减有效预留才是可用余额，D1 报表和 UI 不能覆盖账本。拒绝下一调用的回合先保存再等待用户继续；乙的余额不受影响。支付成功跳转仍显示待确认直到可信入账。
- **处置与验证证据：** 对两个 Workspace 发并发预留，核对守恒式；重复、乱序、延迟和伪造回调；覆盖预留后未派发、派发后未知、重复结算、取消和补偿。核对 Token 类别、不可变价目表与整数舍入；固定未知消费最大处置时限和负责人后才能收费。
- **阻断：** P0，C2；处置与成本数据不完整阻断 C3；关联 R14、R15、R18。

### T15：平台发布机场模型 1.1，并撤回有缺陷版本

- **触发与首次实现风险：** 管理员从用户项目直接打包，把私人资料、Session 或密钥混入官方版本；上传替换同一对象导致既有项目变化；“validated”仅来自页面按钮。
- **修正后再推演：** 发布包使用受审查的文件清单、许可和来源；固定摘要并运行真实最小模型、固定种子和不变量验证，验证证据关联该摘要。发布只能创建不可变版本；撤回阻止新复制并说明原因，既有项目保留独立副本。
- **权威状态与用户表现：** 官方版本状态由受授权的发布流程产生，审计记录操作者与证据；用户可另建 1.1 项目，原项目不自动更新。模型库的验证标记明确是工程验证及其已知限制。
- **处置与验证证据：** 待发布包放入应排除的私密夹具，验证拒绝；修改包内容应使旧验证失效；撤回后重试创建失败，既有甲乙项目哈希保持不变。模板供应链也使用依赖锁与许可检查。
- **阻断：** P0（泄露或覆盖）/ P1（假验证），C1；固定 Starter 在 M3 先执行同类检查；关联 R03、R16。

### T16：发布新 runtime 后恢复失败，成本和任务开始异常

- **触发与首次实现风险：** 一次替换所有镜像；新版本不能读旧 Session / Checkpoint；活跃任务中途被杀。回滚镜像却不能回滚已破坏的数据格式；持续 Preview、Observer、下载大日志使无 Token 任务仍不断产生成本。
- **修正后再推演：** 产品首次上线即可定义自身版本的读取兼容窗口和发布清单；这属于本产品发布恢复能力，不引入旧系统迁移责任。新 runtime 先在隔离环境恢复保存夹具，再用于内部及少量邀请 Workspace；已运行实例排空或按明确维护流程保存后替换。元数据变更先扩展兼容、后切流，破坏性清理另设窗口；镜像和配置都有回退入口。
- **权威状态与用户表现：** runtime 摘要、协议 / Checkpoint schema、发布批次与 generation 可追溯。故障发布暂停扩量，新项目按健康版本创建，受影响项目恢复或标明中断。运行额度控制所有进程，成本停发不阻止保留期内的读取与导出。
- **处置与验证证据：** 预发布验证 N 版本读已有保存夹具、回退版本可读其允许期间的新数据；检查活跃任务处理和恢复演练。记录每次建模、Preview 空闲、Observer、实验、日志与存储成本；设定可执行的配额、保存余量、告警和停止新增工作开关。任何兼容假设和金额阈值未验证前不扩大上线。
- **阻断：** P0（已保存数据无法恢复）/ P1（发布或成本不可控），M0 定契约、M5 验收，C3 用真实成本复核；关联 R13、R17。

## 5. 推演后形成的实现调整

这些调整把已有设计要求转为可验证的开发约束；不等于代码已经修改或能力已经上线。

1. **先验证同一项目中可信 Pi 与项目执行域之间的边界。** 按 ADR 0001 分离两者；M0 不能只证明两个租户有不同 VM，还必须验证 SDK 资源加载、进程身份、受保护目录和控制能力。达不到边界时调整可信组件部署位置，不能靠提示词补救。
2. **先建立权威收据，再接 UI 成功态。** 文件保存、Run 完成、停止确认和消费结算各有不同收据；项目代码、LLM 回复和前端计数不创建这些收据。
3. **让恢复设计贯穿第一次可写回合。** 事务队列、写入协调、Checkpoint、generation 和未知副作用对账必须在 M2 同时形成；不能等全功能完成后追加持久化。
4. **用独立项目应用证明平台边界。** 机场 Starter 必须真的从文件运行，平台无需知道保障组字段。M3 在主旅程之外用一个最小第二应用验证通用托管和观察边界。
5. **为外部不确定性保留明确状态。** LLM 调用未知、取消待确认、保存失败、观察降级和部分实验失败分别处理；不能合并成“失败后重试”按钮。
6. **把资金与运行资源从 Workspace 中提升到 Tenant 协调。** 基础 MVP 先记录真实用量和原子资源占用；C2 才开放按价目表预留与结算，并验证多项目并发和对账。
7. **用本产品自身版本兼容和真实成本决定发布。** 记录镜像、依赖、Skill、协议和保存格式版本；发布回退不破坏保存数据。计量包含容器、Observer、存储及平台故障差额，再确定付费策略。

## 6. 后续执行证据如何归档

每轮验证建立独立、不可覆盖的证据目录，最少记录测试范围、代码 commit、平台配置摘要、SDK / runtime 版本、环境、时间、预期、实际结果和负责人。文件、Session 或日志证据使用合成数据并脱敏；不把密钥、访问令牌和用户私有内容收入测试报告。

建议每个案例以 T01–T16 和 R01–R18 关联：

| 证据类别 | 内容 |
|---|---|
| 请求与事件 | 请求键、Turn / Run ID、generation、事件序号、状态转移与拒绝原因 |
| 保存与恢复 | Checkpoint manifest、摘要校验、恢复版本、Session 关联与未保存范围 |
| 执行与模型 | 固定输入、参数和种子清单、退出码、子任务收据、实际结果与失败统计 |
| 权限与 Preview | 双用户权限矩阵、源地址绕行测试、Cookie / 资源 / WS / 撤销结果 |
| 资金与成本 | 供应商请求关联、usage 原始分类的脱敏证明、价目表版本、预留与账本守恒、支付测试通知 |
| 发布与回退 | 发布清单、批次、保存格式兼容测试、排空 / 停发 / 恢复操作及其实际结果 |

验证报告必须区分 `未执行`、`通过`、`失败`、`阻断`；局部或条件满足只在范围说明中记录，不作为整项门禁通过。使用 mock 的结果标明测试替身覆盖范围；本地通过不能替代实际云 runtime、真实供应商和选定支付渠道的验证。故障解除后重跑关联正常旅程与负向案例，才能关闭风险条目。
