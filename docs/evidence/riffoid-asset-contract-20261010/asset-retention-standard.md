# Existing asset-set retention contract — 2026-10-10

This round implements the authorized `keep-assets-contract-v1` gate. It accepts retention of the existing asset set independently of complete content auditing. It grants no live publication or experiment authorization. The older [design proposal](../riffoid-release-preparation-20261010/assets-acceptance-design.md) is historical; its assumed `runtime.assets` readback is superseded by the evidence states below.

The [official direct-upload contract](https://developers.cloudflare.com/workers/static-assets/direct-upload/) supports reusing existing assets with `keep_assets:true`. The [Worker upload API](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/methods/update/) makes explicit `assets` uploads take precedence. Every prepared upload therefore requires `keep_assets:true` and rejects the entire own `metadata.assets` property, including null or undefined. Multipart module names `metadata`, `assets`, `_headers` and `_redirects` are forbidden. No mutable acceptance flag can substitute for computed evidence.

Both Workers require frozen snapshots containing the standard, exact account and Worker, authoritative inventory `has_assets`, the sorted asset-binding digest, configuration-evidence state and optional configuration digest. No-assets scopes are frozen and rechecked too. The snapshot digest participates in the existing resource identity ledger. Bindings, modules, namespace identities and container associations remain required alongside the asset contract; pipeline, deadline, lock, unknown-request and no-retry guards remain active.

| State | Required observation | Accepted claim |
| --- | --- | --- |
| `NO_ASSETS` | Authoritative false `has_assets`, empty asset bindings and no own runtime assets property | Frozen absence in this Worker scope; no content audit |
| `NOT_EXPOSED_BY_VERSION_API` | Authoritative true `has_assets`; runtime assets property absent | Existing asset-set retention by keep-assets contract and frozen presence/bindings; configuration readback unverified |
| `OBSERVED_ROUTING_CONFIG` | Authoritative true `has_assets`; actually returned, strictly checked routing configuration | Retention contract plus matching observed configuration digest |

The [version API schema](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/versions/methods/get/) does not define assets configuration under `script_runtime`. Absence is therefore represented honestly rather than treated as a missing byte audit or fabricated configuration verification. An actually exposed configuration is restricted to `html_handling`, `not_found_handling` and bounded array path rules for `run_worker_first`; only its digest is retained. Explicit null, malformed data and unsupported fields are rejected. A frozen observed configuration cannot change to unexposed, nor can any other frozen state/digest change be silently accepted.

`assetContractAccepted` is recomputed from the frozen snapshot and upload controls. `assetConfigReadbackVerified` is true only in the observed state. `configUpdateClaim` is `NO_CONFIG_UPDATE_REQUESTED`; unexposed configuration is not claimed preserved by readback. `assetBytesAudited`, `assetSetIdentityVerified` and `contentInventoryAudited` remain false, and `contentSHA256` remains null. No complete asset manifest or content-byte proof is invented.

`preservationMatches` requires main-module, metadata, modules, named resources, containers and the retention contract. `fullStateMatches` additionally requires asset coverage, so it remains false for a Worker with assets. Publisher pre/post checks, terminal replay, GET-only restart, reconciliation and coordinator receipts share the same recomputation. Read-only restart also rechecks both Workers' fixed-version bindings and asset inventories before adoption.

Local and independent six-suite checks each passed 105/105; typecheck and diff checks passed. Retained failed fixture runs explain repaired expectations. Independent extra counterexamples reject cross-scope snapshots, fake audit flags, configuration-state changes, explicit null and unsupported sensitive fields before reading their values. See [summary](summary.json), [review](independent-review.json), [hashes](source-hashes.json) and [counterexamples](independent-counterexamples.json).

This is offline acceptance only. A real authenticated raw-response client, authoritative container association readback, fresh scoped baselines, operational publisher pause and exact run/window inputs remain deployment-time requirements. Application terminal evidence and late-telemetry handling follow the already approved risk record; this change does not restore a platform-wide absolute drain requirement. Complete asset-byte audit is a separate unperformed scope, not an automatic extra prerequisite for this retention standard.
