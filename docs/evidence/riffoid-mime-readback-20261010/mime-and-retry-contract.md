## Byte and redirect acceptance

`riffoid-validation-mime.mjs` recognizes strict CRLF MIME framing and a single bounded boundary. Module `name` binds to the frozen descriptor. Filename is optional; if present it must agree. Headers, boundary, module count and body are bounded. Missing/duplicate/unfrozen entrypoint, duplicate/missing/extra module, ambiguous disposition, encoded content, malformed/folded/duplicate headers, missing closing boundary, epilogue and length mismatch reject. Source payloads are never decoded, normalized, trimmed or reconstructed. SHA256 and exact module length must still match the frozen package. Multipart framing CRLF is excluded; the source's own trailing CRLF remains intact.

Both raw and SDK bridges request manual redirects and reject redirects before reading the body. SDK raw response preserves entrypoint, content type and length/encoding headers; SDK retries remain zero. HTTP Content-Length is checked against bytes when the response is unencoded/identity. Compressed HTTP length is not confused with the decompressed Response body; frozen module length/hash still applies.

Counterexamples include Chinese/emoji/combining characters, invalid UTF-8/NUL, LF and CRLF, empty/multiple modules and wire reordering, boundary-prefix lookalikes, malformed/truncated delimiters, payload truncation, duplicate entrypoint headers, 301/302/303/307/308, already-followed responses, and mismatched HTTP/part lengths. Existing resource, cross-account drift, journal, lock, restart, expiry and unknown-identity suites remain active.

## Method boundaries adopted after independent review

- Allowlisted semantic read-only control-plane GET may use the existing host's bounded retries. No outer retry or provider fallback is added. The raw bridge defaults to15s per call (configurable up to30s); `collectReadback` defaults to60s overall,15s per caller GET,128 caller GET dispatches. Review-only tighter budgets are supported within hard caps120s/256. Exhausted time/count stops further caller dispatch; late responses cannot become accepted evidence. Receipts report start/end/elapsed/count and explicitly unknown proxy HTTP attempt count. These are caller observation budgets, not attestations of the host or all middleware.
- Readback brackets current deployment/latest version, settings/global settings, namespaces, existing container/configuration associations, assets and pipeline inventories. Drift rejects even when the Worker version is unchanged. This is not an atomic platform snapshot; exact-interval coordination and fresh baseline are still needed before a future write. Existing publication checks recheck the approved deadline and lock before any dispatch. Inability to disable **GET** proxy retry is not an absolute deployment blocker by itself.
- **PUT, experiment/provider calls and other budget-consuming actions remain blocked through the replaying or unverified host.** The current raw adapter rejects every non-dry-run PUT before invoking authenticated fetch, even in live mode. SDK and connector bridges remain GET-only; paid/non-control paths are not allowed. An eventual write adapter must separately establish non-replay at every layer. Caller flags, one application invocation, successful status, idempotent naming or a journal do not establish it. Dry-run still builds all exact multipart packets without network.

The independent method conclusion was available before adopting these boundaries. This does not relax application budgets, unknown-request isolation, original identity, journal/lock retention, assets retention, namespaces, containers or stop conditions. The previously approved application terminal/late telemetry standard is retained; no absolute platform drain prerequisite is introduced.
