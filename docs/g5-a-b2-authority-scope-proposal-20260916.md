# G5-A B2 measurable authority proposal

Date: 2026-09-16. Status: explicitly authorized at 19:38 +0800; implementation in progress, not deployed or executed. The same-Turn repair fixture and fail-closed two-stage authority infrastructure are integrated locally. The read-only reopen/export driver slice is implemented and documented in [G5-A B2 read-only evidence driver](g5-a-b2-readonly-driver-implementation.md); scenario inputs, trace output, full authority acceptance joins, integration review, closed-gate deployment, and exact readback remain before execution.

The original frozen repair path cannot be executed honestly. The product has no ordinary-user endpoint that can seed a failed file before a Turn, and a failed `project_bash` result is a completed Tool effect with a nonzero child exit rather than a failed artifact or failed Revision. Proposal B moved the failure and repair into the same ordinary-user Turn. Its final prompt/fixture candidate is independently reviewed, omits the repair payload and private receipts, and has SHA-256 `c31c76ec54074f59d9aacc834b2641ce8e130637834dd8cf8e6e8927c9961bad`.

A two-stage production authority now proves the post-Turn source/tool facts, persists a predecessor chain, then checks post-Run/Group/Claim state. It correctly fails closed because seven original assertions are not represented by current durable evidence: optional full traces, a comparison assigned to the wrong fixture, unexecuted `max_wait=0` and `queue_capacity=0` scenarios, generic validation/export identities, natural-language meaning, and an unfenced reopen/read interval. It returns the unsupported checks, writes no terminal receipt, and admits no successor. A Workerd integration regression exercises the real Guard persistence path for stage-1 replay, unsupported no-write, identity conflict, and terminal replay across restart. B2 implementation must extend that harness for its accepted terminal path and full Workspace evidence joins.

B2 replaces those unobservable assertions with evidence that the existing product can produce under the same budget and research intent:

1. Keep 3 Projects, 18 ordinary-user Turns, 39 Simulation Runs, 3 Group tasks, concurrency 1, 63 normal admissions, up to 3 terminal probe Turns, 66 maximum tasks, 147 maximum upstream dispatches, US$20 total, and US$5 per Turn.
2. Run the mechanism-change boundary at `max_wait=0` instead of 2. The fixed synthetic seeds retain one Run per repetition and permit direct conservation, abandonment, zero-positive-wait, and queue checks.
3. Run the reopen intervention at `queue_capacity=0` instead of 2, keeping the baseline at 120. This preserves two Runs per repetition and permits direct rejection, conservation, and zero-queue checks.
4. Add a bounded `trace-audit.json` output for every Run. Its closed schema contains only frame, time, queue length, completed, abandoned, rejected, active, and waiting values. It is capped at 16 KiB; the current fixed inputs project to about 2–3 KiB. Authority reads the result envelope and audit through bounded private storage, verifies both hashes, then recomputes finite/nonnegative values, frame order, conservation, and `queue_length == waiting`.
5. Inspect every Group child individually. The driver and Workspace authority must verify the exact two configurations by three seeds, each child artifact/audit, release proof, and the verified throughput-delta claim. This covers all 39 Runs rather than treating a terminal Group summary as child evidence.
6. Before the reopen Turn, execute a bounded same-origin ordinary-user read sequence for workspace, files, model, historical Run/Group/evidence detail. Compare Guard snapshots before and after and require zero delta in tasks, dispatches, money, model usage, Runs, and Groups. Bind the response hashes to the same project, prior Revision, source digests, and historical IDs.
7. After the reopen Runs and claim, read the research export without task admission. Require HTTP 200, ZIP media type, `no-store`, matching header/body SHA-256, a 16 MiB ceiling, a valid manifest, and entry-by-entry hashes for historical and current source/result evidence. Require another zero-ledger-delta proof around the GET.
8. Mark only machine-recomputed assertions as `verified`. Preserve the model's explanation and served-only interpretation as `unassessed` with Turn references; no natural-language assessment may become an authority `satisfied: true` claim.

The category mapping remains recognizable: create proves the source layout, Spec, Revision, baseline Run and trace audit; parameter-change proves unchanged source and two same-seed inputs/artifacts; mechanism-change proves a new abandonment model at `max_wait=0`; repair proves six Tool Ledger facts, restored source, new Revision, and a Run; measured-evidence proves the six-child Group and verified numeric claim; reopen proves the read-only interval, capacity model, 120/0 Runs, stale historical Run, and export.
