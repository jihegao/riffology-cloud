# G5-A B2 read-only evidence driver

Date: 2026-09-16. This local slice implements the authorized B2 read-only proof around each `reopen-continue` Turn. It does not deploy, open a gate, submit a task, start a Run, or call a model.

`scripts/model/g5-b2-readonly-proof.mjs` accepts only same-origin ordinary-user GET responses and private authority snapshots. Before each reopen Turn it reads, in serial order, the Workspace, files, model, every historical Run, every historical Group, and every historical evidence claim. It requires HTTP 200 JSON, hashes the exact response bytes, and binds the sequence to the A window, tenant, Project, Workspace, prior Revision, files and Spec digests, and the exact historical IDs.

The Guard now opens a single-use read session from the persisted before snapshot and the exact server-derived inventory. The WorkspaceAgent stamps `createdAt` and `expiresAt` with a fixed 30-minute TTL and persists both values; restart cannot extend the deadline, and the exact `expiresAt` boundary is already expired. The browser sends the opaque session ID and capability only on that fixed GET sequence. After normal Cookie authentication and route authorization, the main Gateway clones the actual response, hashes its exact body bytes, and asks the WorkspaceAgent to append `{path,status,bodySha256}`. The WorkspaceAgent accepts only the bound user/auth version, tenant, Project, Workspace generation, window, Revision and next expected path. Wrong order, scope, status, digest, capability, an expired session, or an extra/reused request fails closed. The capability never appears in proof output.

The private authority snapshot has exact counters for tasks, upstream dispatches, charged money, model input and output usage, Simulation Runs, and Groups, plus active, pending, and unknown counts. Both snapshots must be settled, and every counter must have zero delta. Only then, and only before `expiresAt`, can authority seal the complete server-recorded read session, persist `consumedAt`, and bind its receipt and all three timestamps to the interval attestation. Repeating the identical call after response loss replays the same sealed receipt while it remains live; the same session cannot record another sequence. A caller-supplied local count or a reused snapshot without the actual Gateway GET records cannot satisfy this interface.

The production operator path exposes fixed actions for snapshot, session start, interval attestation, and reopen-grant consumption: `snapshotReadonlyCounters`, `beginReadonlyReadSession`, `attestReadonlyInterval`, and `consumeReadonlyReopenGrant`. The HTTP client, operator Worker allowlist, and cloud authority adapter forward those payloads to the single global window guard. A missing private implementation fails closed; the driver cannot replace it with process-local counters or a permissive mock.

After the reopen Runs and claims, the driver GETs `/api/workspaces/:workspaceId/research-export`. It requires status 200, an `application/zip` media type, `no-store`, a body no larger than 16 MiB, and equality between the response header and exact body SHA-256. The ZIP parser accepts the product's bounded store-only format, verifies central and local metadata plus CRC, rejects duplicate or unsafe paths, and hashes every entry. The manifest must bind the same Project, Workspace, current Revision, every historical/current source version, Run, Group and claim. Every manifest inventory size and SHA must match the corresponding ZIP entry, and no unlisted entry is accepted apart from `manifest.json`. A second authority-backed zero-delta interval covers this export GET.

`createG5B2CdpReader` performs only whitelisted Workspace GETs inside an existing same-origin browser page with `credentials: "include"`. `createG5ACdpTransport` returns this reader beside its existing JSON transport, so both share the already authenticated page without exporting session material. The reader returns status, selected response headers and bounded response bytes; Cookie values and browser request headers are never returned or persisted.

The main serial driver recognizes the new explicit authorization scope `g5-a-b2-controlled`. That scope fails during initialization unless both B2 proof methods and the reopen-grant authority are supplied. It executes the first proof before each reopen Turn and the export proof after that Turn's two Runs and claims. Immediately before a reopen POST, the driver sends the proof's authority receipt and exact window, Workspace, Revision, and next fixture ID to `consumeReadonlyReopenGrant`. The Guard verifies the persisted attestation, TTL and scope, then atomically issues a grant bound to that next fixture. A prewritten local proof JSON is only a display/cache artifact: forged or stale JSON cannot obtain the grant and causes zero reopen POSTs and zero new admissions. The reopen terminal requires the same persisted grant and live read-session timing; an expired or mismatched old proof cannot finish the fixture. Final authority requires three distinct read-session receipts alongside the six interval attestations and validates that every session, attestation and grant consumption occurred by its original deadline. Historical final inspection may occur later, but does not refresh or waive that deadline. The legacy `g5-a-create-reconcile` scope remains unchanged; using it does not claim B2 acceptance. The existing serial host still owns public-gate-first closure and post-close final reconciliation.

Validation covers the exact GET sequence, identity and Revision binding, wrong-order and wrong-user refusal, expiration before record/seal/attest/grant/terminal, exact Gateway response-body hashing, deadline preservation and receipt replay across Durable Object restart, each forbidden counter delta, export headers/body digest, ZIP inventory and entry hashes, B2 driver order, forged/stale local proof refusal before POST, missing-interface refusal, and Cookie exclusion. A vertical Workerd integration test runs real Gateway GET routes through Catalog authorization, response clone/hash recording, the real WorkspaceAgent session, Guard attestation, and the fixture-bound reopen grant. It also uses a real WorkspaceAgent research export and persisted export receipt, replays its G5 export authority after restart, and rejects wrong-user, wrong-order, expired, digest, and scope mismatches. These are synthetic local tests and do not constitute live G5-A evidence.
