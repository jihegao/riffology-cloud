# G5-A B2 read-only evidence driver

Date: 2026-09-16. This local slice implements the authorized B2 read-only proof around each `reopen-continue` Turn. It does not deploy, open a gate, submit a task, start a Run, or call a model.

`scripts/model/g5-b2-readonly-proof.mjs` accepts only same-origin ordinary-user GET responses and private authority snapshots. Before each reopen Turn it reads, in serial order, the Workspace, files, model, every historical Run, every historical Group, and every historical evidence claim. It requires HTTP 200 JSON, hashes the exact response bytes, and binds the sequence to the A window, tenant, Project, Workspace, prior Revision, files and Spec digests, and the exact historical IDs.

The private authority snapshot has exact counters for tasks, upstream dispatches, charged money, model input and output usage, Simulation Runs, and Groups, plus active, pending, and unknown counts. Both snapshots must be settled, and every counter must have zero delta. A strict authority attestation binds both snapshot receipts to the read sequence hash. A caller-supplied local count cannot satisfy this interface.

The production operator path exposes only two additional fixed actions, `snapshotReadonlyCounters` and `attestReadonlyInterval`. The HTTP client, operator Worker allowlist, and cloud authority adapter forward those payloads to the single global window guard. A missing private implementation fails closed; the driver cannot replace it with process-local counters or a permissive mock.

After the reopen Runs and claims, the driver GETs `/api/workspaces/:workspaceId/research-export`. It requires status 200, an `application/zip` media type, `no-store`, a body no larger than 16 MiB, and equality between the response header and exact body SHA-256. The ZIP parser accepts the product's bounded store-only format, verifies central and local metadata plus CRC, rejects duplicate or unsafe paths, and hashes every entry. The manifest must bind the same Project, Workspace, current Revision, every historical/current source version, Run, Group and claim. Every manifest inventory size and SHA must match the corresponding ZIP entry, and no unlisted entry is accepted apart from `manifest.json`. A second authority-backed zero-delta interval covers this export GET.

`createG5B2CdpReader` performs only whitelisted Workspace GETs inside an existing same-origin browser page with `credentials: "include"`. `createG5ACdpTransport` returns this reader beside its existing JSON transport, so both share the already authenticated page without exporting session material. The reader returns status, selected response headers and bounded response bytes; Cookie values and browser request headers are never returned or persisted.

The main serial driver recognizes the new explicit authorization scope `g5-a-b2-controlled`. That scope fails during initialization unless both B2 proof methods are supplied. It executes the first proof before each reopen Turn and the export proof after that Turn's two Runs and claims. The proofs are persisted in the existing mode-0600 durable journal and are shape/binding checked before reuse, so pending supervision does not repeat a completed export. The legacy `g5-a-create-reconcile` scope remains unchanged; using it does not claim B2 acceptance. The existing serial host still owns public-gate-first closure and post-close final reconciliation.

Validation covers the exact GET sequence, identity and Revision binding, each forbidden counter delta, export headers/body digest, ZIP inventory and entry hashes, B2 driver order, unchanged POST count, missing-interface refusal, and Cookie exclusion. These tests use synthetic responses and authority adapters; they do not constitute live G5-A evidence.
