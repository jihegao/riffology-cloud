# G5-A serial live driver

`g5-a-live-driver.mjs` is the reviewed-host orchestration layer for the frozen #46 benchmark. Its default CLI prints the immutable dry schedule and `--execute` is rejected. Direct `G5ASequentialLiveDriver.execute({execute:true})` is also rejected; the only mutation entry is `runG5ASerialHost`. The host opens the exact five public gates, supervises one concurrency-one workload, closes and reads back those gates in `finally`, then closes the Window Guard. A successful result is returned only after a post-close authority reconciliation. No cloud, model or Run was invoked while implementing this module.

The schedule is project-major and concurrency one. Each of three projects has one Session and six dependent Turns in the order create-model, parameter-change, mechanism-change, repair-validation, measured-evidence, reopen-continue. Run counts are 1, 2, 1, 1, 6 and 2. The measured step uses one Experiment Group containing baseline/intervention across three frozen seeds; other steps use ordinary Experiment requests. The named counts are `normalAdmissionTasks=63` for 3 Projects + 18 Turns + 39 child Runs + 3 group intents, `probeTasks=3`, and `maximumAdmissionTasks=63+3=66`. The first failed, unknown or otherwise unqualified probe closes admission and prevents later probes.

Every mutation uses the existing wx/fsync `DurableOrdinaryRunner` journal and deterministic idempotency key. An intent without an ACK is never reposted and blocks all subsequent mutations. A persisted Project ACK is reconciled through the public `GET /api/tenants/:tenantId/projects/:projectId` route with bounded read-only polling until `ready`; only then may the Workspace and Session be read or created. Known Project, Turn, Run and Group pending states make the serial host wait and repeat read-only reconciliation in the same process. They do not close the window or admit a successor. The supervision loop is bounded by the authoritative guard deadline; exhaustion or an unsafe authority state stops admission. An out-of-process crash still requires the external deadline/closed-gate reconciler.

Each task checks the saved Turn, exact Revision/files/source version, five required source paths, trusted tool and provider receipts, and closed model/money/tool ledgers with zero pending/unknown. Each individual Run requires a trusted release receipt; each Run or completed Group creates and independently GET-verifies a persisted evidence claim. Immutable sanitized receipts are stored mode 0600 with directory fsync. Raw prompts are present only in the frozen fixture and outbound product request; session cookies and response bodies are not written by the driver journal.

Authentication uses `createG5ACdpTransport`. It attaches to one existing same-origin Chrome page and performs `fetch` inside the page with `credentials: "include"`. Before execution it confirms `/api/me`, a 200 project list for the authorized A tenant and 404 for the B tenant. Before every POST it repeats `/api/me`. Its exact proof binds the A user and tenant, denied B user and tenant, ordinary origin, A window and exact open-configuration SHA. The operator and driver validate the same hashes. Cookie bytes and raw identity responses never leave Chrome. The transport rejects redirects, non-product paths, non-loopback CDP endpoints, wrong origin and responses over 1 MiB.

Deadline, budget or identity failures surfaced by authority, failed/cancelled Turns or Runs, unknown delivery, invalid source/claim/ledger evidence, release uncertainty, probe uncertainty and final inventory mismatch return control to the serial host. The driver never closes the private guard by itself. Host closure always deploys and independently reads back all five public gates as false before invoking private guard closure. A delivery-unknown POST remains fenced because the public API has no intent-key lookup that can recover its entity ID.

Task accounting is authority-backed. Initialization requires a private receipt proving that each of the three Experiment Group intents is itself admitted as a guard task. Final reconciliation requires the guard to report `tasks = 63 + executed probes`, including three Project tasks, 18 Turn tasks, 39 child Run tasks and three Group-intent tasks. Local schedule arithmetic cannot satisfy this check. Until production authority can issue that receipt and final count, live execution fails closed.

The authorized B2 slice adds the explicit `g5-a-b2-controlled` scope. That scope requires the [B2 read-only evidence driver](g5-a-b2-readonly-driver-implementation.md): a same-origin, authority-fenced read sequence before every reopen Turn and a fully verified research export after its Runs and claims. Both intervals require zero change in task, dispatch, money, model-usage, Run and Group counters. These GETs do not increase the frozen 63 normal admissions.

## Required execution inputs and remaining product/API gaps

A real host still needs these private, reviewed inputs; tests use synthetic adapters only:

- a running Chrome CDP endpoint with the already authenticated first ordinary test user, the exact user ID, A tenant ID and denied B tenant ID;
- the frozen config and out-of-band SHA, writable 0700 journal directory, exact-release/profile/window preflight adapter and operator reference;
- a trusted authority adapter that reads the private G5 guard, provider usage, money and tool ledgers, actual Group-intent task admissions, Run release state and paginated final inventory, and that can durably close admission;
- trusted two-stage `inspectFixtureTask` and `inspectFixtureTerminal` authority RPCs. Proposal B pins fixture manifest `c31c76ec54074f59d9aacc834b2641ce8e130637834dd8cf8e6e8927c9961bad`; its repair Turn performs six Tool Sandbox calls in the same Turn. Stage one must bind their order, unique identities, receipt digests, failed/repaired file SHA-256 values and compile outcomes before a Run. Stage two must bind the stage-one receipt and source to authoritative Run/Group/release/claim state before the next fixture;
- optional probe preparation/inspection adapters. Probe Turns themselves use the same ordinary CDP/journal path, but fault selection and private ledger observation are not exposed by product HTTP;
- a read-only reconciliation API keyed by idempotency key would be required to resolve a lost POST ACK. Until then, an ACK-less intent stops the window and is never retried.

The public individual Experiment view omits release state, so `inspectRun` must obtain it from trusted storage/inventory. The public Turn/workspace endpoint also cannot prove provider usage or all three ledgers. These adapters are required before live execution; caller-supplied booleans are rejected by the strict receipt schemas.

Proposal B remains a review-only, unauthorized path. Unsupported domain evidence makes stage two return `accepted:false`, prevents a terminal receipt and stops the successor fixture. This change does not claim those production adapters exist or authorize live execution.
