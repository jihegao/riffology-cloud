# G5-A private authority RPC

Status: implemented and tested locally on the integration base; no Worker or Durable Object was deployed by this change.

`G5ControlledWindow.operatorSnapshot()` is now the single private aggregate for the active frozen window. It starts from Guard-owned task, call, Turn, deadline and closed state, then resolves every persisted `runtime_identity` against the fixed G5 token namespace, production money actor and per-dispatch Tool Bridge actor. It reports task and dispatch counts, group intents, Simulation and Service Run counts, deadline origin, pending and unknown counts per domain, recorded/reserved money occupancy and the maximum occupied Turn. A missing binding, malformed settlement, identity mismatch, read timeout or money-reference conflict throws; the temporary operator Worker returns only `operator-unavailable` in that case.

`inspectTask` does not accept receipts from the caller. The Guard resolves the bound Turn task and its persisted runtime identity, asks the exact Workspace actor for the terminal saved Turn, current checkpoint/version and retained completed tool event IDs, and joins that proof to closed token, money and tool settlements plus each Guard-persisted authority-call context. The requested fixture ID must also match the Workspace's durable ordinary-user request key `${windowId}-${fixtureId}-turn`; it is not echoed as identity evidence. The current implementation intentionally fails closed if the inspected Turn is no longer the Workspace head or its completed tool events have left the retained event window. The serial driver inspects immediately after each Turn, before admitting the next one.

`inspectRun` first resolves the globally unique Guard task whose `bound_id` is the requested Run. It then selects the Workspace from a Guard-persisted Turn identity and requires the Workspace's private Simulation record to match the same G5 task key, tenant/user scope, Run ID and artifact hash and to be `completed`, released, and backed by a non-null platform release proof. The fixture ID must match the durable request-key prefix `${windowId}-${fixtureId}-run-` and a positive Run ordinal. A caller boolean or caller-only fixture label is never used.

`inspectFinal` compares the complete set of Guard-bound Simulation Run IDs with all G5 Simulation records found in the three authoritative Workspace actors. Each Run must be `completed`, released, and backed by a non-null platform release proof. It also compares Guard-bound `group` task IDs with actual Workspace group records, requires each Group itself to be `completed`, and requires every child to be one of those terminal released Runs. Project, Turn, Run, group-intent-task and total-task counts, plus the admission `closed` flag, come from durable Guard state. The caller's expected counts are bound into the final receipt but do not create or override observed counts; an open window is returned as `closed: false` for the hardened driver to reject.

`inspectAdmissionContract` accepts no payload. It derives the 63 normal tasks, 66 maximum tasks, three group-intent tasks and `guard-task` admission mode from the persisted Phase A policy and fixed task rules, then hashes that derived contract. A 63-task legacy policy or any other policy shape fails closed.

Group creation is now a first-class G5 task. `kind: "group"` consumes the global task limit while leaving `maxSimulationRuns` unchanged. `submitExperimentGroup` derives the parent from the Workspace's saved head and its private G5 Turn route, registers and claims the group task before local creation, then binds the durable group ID and obtains and confirms a one-shot start grant. If the Workspace commit succeeds but a Guard RPC acknowledgement is lost, an identical retry replays the local group and completes bind/start confirmation. If creation fails after the Guard claim and no local group exists, the claimed task remains a global hold; it is not refunded or bypassed.

The temporary operator Worker exposes only capability-protected POST actions `snapshot`, `inspectAdmissionContract`, `inspectTask`, `inspectRun`, `inspectFinal`, and `close`. Its only binding remains the global Guard actor; ledger and Workspace namespaces stay private to the production Worker. `createG5AuthorityAdapter` maps an in-Worker stub to the serial driver's authority interface. `createG5OperatorHttpAuthority` is the bounded Node-side client: it calls only `/operate`, refuses redirects, limits response bytes, keeps the capability request-only, and performs the snapshot-digest close handshake before returning a sanitized close receipt. The Worker must still be deleted after evidence collection.

Validation: TypeScript typecheck, 62 focused G5 tests, and eight Workspace authority/model-proxy integration tests pass. The Workerd test proves a closed parent Turn can authorize exactly one persisted group task, that the group consumes task capacity, and that it does not consume Simulation Run capacity. All proofs in these tests are local fixtures; production authority remains unverified until the exact release is deployed and read back.
