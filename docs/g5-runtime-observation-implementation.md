## Actual local durable journal adapter

`g5-runtime-intent-journal.mjs` supplies createOnce/update/read/recordReconciliation. It requires an existing parent directory; creates the journal directory with mode0700, synchronizes it and its parent, records one window identity, takes an exclusive wx window lock, and uses mode0600 wx evidence files with file and directory fsync. Crash-stale or uncertain lock is blocked and never automatically removed. Same-key identity fingerprint conflicts fail; only the unique durable created owner may POST. Any unresolved unknown/submitted intent blocks new keys across the window. ACK and terminal reconciliation are separate immutable files, preserving the original delivery-unknown fence permanently; existing keys always reconcile rather than regain POST permission.

The adapter persists only identity, messageSHA, state and receiptSHA, never Cookie or raw prompt. Updates require exact Workspace/Session/messageSHA plus a stable Turn identity. Reconciliation requires its separately supplied exact-scope terminal receipt and raw evidence hash. The adapter enforces local association and durability, not authenticity of cloud observations; caller-supplied receipts do not manufacture native authority or qualify the blocked main runner. Production receipt collection/verification remains required. Nineteen tests previously passed; an additional ACK/scope-conflict test brings the focused suite to twenty. Tests reopen the actual filesystem journal, race actual adapter-backed submissions, preserve unknown ACK/crash locks and verify secret exclusion. No live model/cloud requests occur.

Ledger admission hardening: terminal product state alone never unlocks new mutation. Reconciliation requires three independent tokens/money/tools receipt hashes, exact window/intent/Turn/Workspace/Session/messageSHA association, explicit settled status and active/pending/unknown zero. An operator-owned verifyLedgerReceipts adapter must independently verify their authority and return a verified receipt-set hash; missing callback or Boolean caller assertion always rejects. This repository does not supply a real cloud authority verifier, so the default journal never accepts reconciliation or unlocks a new key. Synthetic tests inject only a labeled fixture verifier to exercise local association. Absence of ACK, missing usage, any unknown ledger and reopening without the verifier all preserve the window hold. Main live preflight remains blocked; no cloud authority claim follows from local journal tests.

Receipt privacy/TOCTOU update: the journal constructs a copied, frozen canonical receipt and three frozen domain snapshots before awaiting the verifier. Only windowId/intentKey/Turn/Workspace/Session/messageSHA/status/counts/rawEvidenceSHA survive normalization. Extra ledger fields (including Cookie/rawPrompt) are discarded; unknown domains are rejected. Hashing, verifier input and persistence use the same snapshot. Twenty-three focused tests pass, including nested secret exclusion and mutation of the original caller object during callback without changing the persisted hash-bound snapshot.

## Private trusted ledger-source design

Obtain TurnRuntimeIdentity from the internal authoritative Turn journal, not a public caller: exact scope (tenant/project/workspace/workspaceGeneration), Session, Turn, dispatch and matching generation. For the forthcoming G5 release select its G5_TOKEN_BUDGET namespace; historical G4 records retain their original token namespace. Do not retarget historic identities or infer a G5 binding exists on older sources.

Fixed private reads are tenant token actor derived by modelBudgetTenantName(tenantId), production money actor PRODUCTION_MONEY_ACTOR, and tools actor derived by toolBridgeActorName(scope,turnId,dispatchId). Invoke respective turnSettlement RPCs (token takes tenantId plus identity; money/tools identity). Each DO validates its derived actor. Actual fields are schemaVersion/domain/identity/closed/closedAt/total/active/unknown/pending; token domain model maps explicitly to journal tokens. Require exact identity, closed true, valid positive closedAt and active/pending/unknown zero, then hash actual private raw bytes and bind their fixed namespace/actor/release provenance. Verify actual data through an operator-owned adapter, not a caller's Boolean proof.

Read only after the whole Turn reaches its authoritative terminal boundary. Do not close admission after each model call: that would prevent nonce task follow-up calls. Existing workspace handoff owner closes the three Turn admissions at terminal; observation never invokes closeTurnAdmission or closeWorkspaceRuntime to force success. turnSettlement may initialize existing ledger schema, so no new execution is not a zero-storage-write promise.

Public whitelist should retain domain/schema/counts/closed/time, rawSHA, identitySHA, actorNameSHA, namespace ID, frozen source/version and observedAt. Full scope/actor identities, request Cookie, prompts, capabilities and raw private records stay private. Ledger bytes have no intrinsic receiptSHA/signature: SHA is computed by trusted collection and proves integrity with source provenance, not provider invoice settlement or native PID/absence/guard. Journal identity fields remain private mode0600. This design does not create a new public RPC forwarding endpoint or complete cloud authority.
