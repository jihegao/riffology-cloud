# G5全局受控窗口第一切片

状态：本地core/private DO/独立token namespace接口实现；没有生产接线、namespace创建、门禁开启、模型请求或云Run。本实现不构成G5执行授权。

`G5ControlledWindow`只允许固定actor `g5-controlled-global-v1`。当前policy只能取服务端环境，客户RPC不能指定windowId；SQL按windowId保存不可变policy、首个实际平台guard准入的startedAt与单向closed。准入commit时启动最长2小时；若durable sync跨截止，保留准入fence并返回mayStartNewExecution=false，不能在窗口外创建实体。实体创建可能稍后完成，不将guard准入冒称UI已建立Project或执行已开始。同window改变policy拒绝；重启/版本变更不清零。

冻结候选policy为显式参数，不提供自动默认授权：A允许OpenAI profile pin、147upstream、39Simulation/0Service、63或66task；B强制2不同tenant且不同user、168upstream、0Simulation/0Service、24task；均20USD总额/5USD每Turn，明确rate/profile SHA及单价，时长严格1000至7200000ms。价格只是由已批准policy提供的冻结字段，本地测试合成rate不代表实时价格或用户批准。

准入采用全局SQLite事务与durable sync。Project/Turn/Simulation/Service intent分别计数；重放只读回已有身份，不授权新执行。bindTask存真实实体ID且全局唯一，防同一实际Turn拆多个key获得多份Turn金额。Call绑定turnKey及实际turnId、principal、profile/payload/token reservation摘要；实际Turn必须已bound，才能reserve。金额用BigInt计算，并保守占完整冻结上界。

全局所有window的未绑定task及reserved/dispatched/unknown/settling Call阻断任何新任务或其他Call。新增g5_turns保存真实绑定Turn的open/closed hold；即使某Call已结算，newtask/window仍held。claimDispatch只有当前active window原reserved行能原子获取一次；ACK丢失以后只observe，不再授权。durable sync跨截止返回authorized=false，fence仍保留。

Call与Turn结算分层：usage先进入settling；`settle`仅校验规范化token/money单Call terminal及tool quiescent（允许整个Turn仍open）的绑定与SHA，进入call-settled并允许同一个精确已bound/admitted Turn下一Call。`closeTurn`要求三个真实Turn closed、active/pending/unknown0的规范化receipt以及该Turn所有Call已call-settled，才转Turn closed/Calls recorded，放开新task/window。旧bound Turn保守回填open，不能通过升级丢失未闭账hold。

这两个纯core接口只能检查内部规范化receipt的形状/身份/摘要，不能验证来源真实性。未来private authority adapter必须从真实token/money lookup及tool turnSettlement读取，对整个Turn用真实三账本closed接口；禁止将caller JSON、fixture或自行构造SHA当作等价authority。当前仍无productionexecute路径。Call settle ACK不确定时markUnknown可将call-settled重新保守标unknown；可信reconciliation之前不许同Turn下一Call。

终态收尾按全局唯一callKey查已固化历史policy，因此当前env切到下一window后仍能精确完成旧unknown，客户仍不能选择任意window。没有releaseUndispatched、reset或TTL自动退款接口；未dispatch且ACK不确定的hold无法由verifiedusage自解，需要以后单独评审确证未dispatch的三账本释放流程，当前保持阻断。

`G5TenantModelBudget`是新增独立export，必须绑定新的G5_TOKEN_BUDGET namespace，沿用token core但不加载旧G4 singleton。原TenantModelBudget/G4 env/namespace/budget fence未修改。独立token ledger本身不能授权provider请求；后续共享接线必须按token reserve→global reserve→money admission/dispatch→global claim→token dispatch→一次provider请求，任何ACK不确定不重发，未知usage继续保守全局阻断。第一切片尚未实现这个跨actor网络链，不能据此运行execute。
