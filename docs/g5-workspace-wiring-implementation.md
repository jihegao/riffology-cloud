# G5 Workspace / Turn / simulation wiring

Implementation candidate based on e746cf7; depends on C private grant/authority interfaces (87361b1 initial interface) and Root catalog persistence wiring. No cloud, provider or model execution was performed.

New ordinary Turn submissions under server G5 configuration register and claim their fixed input task, then save an immutable four-field budgetRoute keyed by actual Turn ID before binding the guard task and returning the queued journal mutation. Alarm registration is not execution authorization. Old Turns retain legacy token namespace interpretation. When G5 server configuration is active, absence of a durable G5 route is not legacy start authorization: queued/starting Turns without explicit trusted provenance are denied before capacity/native start. Existing accepted runtime observation and release remain separate. Route conflicts fail closed.

The real FIFO dispatcher checks the start guard before capacity acquisition and claims native start only after the genuine runtime identity exists. Workspace stores its one-time returned grant, syncs local storage, confirms it, and reads fresh continuation permission. A durable native-accept fence is written before the actual accept RPC; acknowledgement loss becomes observe/reconcile only. The strict runtime identity / capability schema remains unchanged, allowing C to authoritatively route Proxy requests by its exact persisted identity.

Cold and warm terminal handling close the actual three Turn ledgers, choosing G5_TOKEN_BUDGET only from the persisted Turn route, then call closeTrustedTurn so C rereads real settlements. There is no per-model-call Turn closure. Workspace alarms retry unconfirmed terminal closure before admitting later work. Queued cancellations invoke the fixed unstarted-task cancellation without inventing runtime identities; Stop cleanup retains legacy exact native release behavior.

Each simulation childRun freezes its own route/admission before the durable run receipt. Capacity and native stages check the owned confirmed task grant against the current deadline/unknown fences; read-only observation and existing stop/release paths are separate. New G5 Service requests reject before Service admission. WorkspaceTask preserves and strictly validates Root's Project budgetRoute; provisioning coordinator checks start before acquire, dispatch and initialize. Root must leave the Project execution grant claim to Workspace, or explicitly transfer a durable grant with a reviewed interface; the four-field route alone is not a start grant.

## Simulation creation durability correction

Simulation admission now only registers/claims creation and returns the route. SimulationHost binds the guard through createdRun only after the actual Run transaction and storage.sync both acknowledge success. Failed child admission/transaction and lost commit acknowledgement never bind, so capacity/native start remains denied. Existing stored Runs may be inspected through explicit private reconcileSimulationCreation/reconcileCreatedRun; that reads the actual durable record and binds its existing ID, without resubmitting a new Run or replacing an unknown mutation. Ordinary GET and idempotent POST replay do not silently perform that repair.

Focused tests exercise real file-backed transaction rejection and commit-ACK loss, proving bind count zero and native starts zero, then independent stored-read reconciliation with no extra registration. Each childRun retains its own admission identity. Inline Native Runs do not currently originate from a ToolBridge Turn in the production submitExperiment/Group API; no parentTurnKey is guessed from active/head identity. A future true tool-origin entry must pass its private authoritative command identity, not a client JSON parent.

## Turn journal durability acknowledgement loss

The journal transaction and its durability acknowledgement precede the accepted-route callback. A committed queued Turn can therefore survive an acknowledgement loss without its G5 route or guard binding. In a configured G5 Workspace, the start hook now rejects that missing route at both capacity and native phases; it never treats absence as permission to fall back to legacy. No caller replay manufactures legacy provenance. Historical unmarked queued work needs separate authoritative reconciliation rather than a fresh start.

Joint Workerd fault tests call the actual storage.sync, wait for its genuine durable commit, and then drop that acknowledgement before the accepted callback. They verify the persisted queued Turn has no route, restart using the same durable storage, and assert an unchanged create-claimed global task, no capacity resource wait/dispatch, and zero native/provider calls. Both cold mode and enabled lazy/reuse mode execute this boundary; no physical warm VM reuse or performance claim is made. Outbound remains disabled.

Validation for this correction: typecheck and all three joint Workerd scenarios pass (original three-ledger closure/window-stop scenario, cold ACK-loss restart, and lazy/reuse-enabled ACK-loss restart). No cloud writes or provider inference occurred.
