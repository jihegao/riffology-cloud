# Internationalization foundation

Issue #128 A supplies the shared bilingual presentation foundation only. It owns
`services/web/i18n.js`, the top-level language selector on the normal site,
Workspace route (including its standalone Browser Preview), and the admin page,
plus the explicit shared-shell strings marked with `data-i18n`. It does not
translate user content, Agent history, model code, Preview content, dynamic
Workspace panels, errors, or the broader product UI; those remain the later B
scope for #126/#129.

The frozen browser API is `t(key, vars, fallback)`, `getLocale`, `setLocale`,
`subscribe`, `formatNumber`, and `formatDate`. `t` never renders a raw missing
key: it takes the current dictionary, then Chinese, then English, then the
provided fallback or an empty string. Placeholder substitution converts values
to text only. Formatting is for rendered labels only, never form input values,
parameter JSON, IDs, request payloads, or ISO values.

Locale resolution is account preference, local preference, browser language,
then `en`. The account preference is optional: failure leaves the page usable
and retains the local selection. Browser selection changes only explicit
platform-owned nodes and attributes; it does not call `load`, reopen a
Workspace, or recreate Preview/session panels. Client hydration and writes are
versioned; writes are serialized and coalesced so an older request cannot
persist after a newer selection, and a late account A response cannot replace a
selection or account B state.

The shared-shell check compares the actual Chinese and English dictionary key
sets and locks the A-scope keys declared by the two HTML shells. Existing
hard-coded product text remains outside A; additions to that text require B
scope review rather than being presented as complete English coverage.

`0011_user_locale_preferences.sql` is additive and must be applied after
`0010_project_budget_routes.sql`, before shipping assets that call
`GET`/`PUT /api/me/locale`. The table is owned by `catalog_users`; both reads
and writes use the current authenticated principal and recheck `active` plus
`auth_version` in SQL. It does not modify Better Auth tables, invitations,
projects, Workspaces, Turns, providers, gates, or billing.

`scripts/i18n-check.mjs` verifies that the A shared-shell declarations have
dictionary keys in both language blocks. New A shared-shell text must use a
stable `data-i18n` key and add both translations. Dynamic UI migration is
deliberately deferred rather than using a DOM observer or translating user data.

The executable guard also compares all `services/web/*.js` and `*.html` CJK
source counts against `scripts/i18n-legacy-cjk.json`. Existing copy may be removed;
new CJK text must enter the dictionary. This conservative check also covers CJK
comments. It does not detect all English hardcoding; English copy and dynamic
translation coverage still require review. The baseline is a legacy exception
inventory, not translation coverage evidence, and must shrink during B migration.
`scripts/i18n-shell-declarations.json` prevents removing the translated shell
attributes. New keys and shell declarations require explicit guard updates.
