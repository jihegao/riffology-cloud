# Chinese and English presentation

Issue #128 supplies the shared language preference (A) and product-copy migration
(B). Both dictionaries cover the ordinary site, Workspace and standalone Browser
Preview, admin, simulation/comparison, evidence, publication, research export,
services and preview panels. Platform labels, notices, errors, placeholders and
accessibility labels change in place. User content, Agent history, code, editable
configuration names, raw JSON and embedded preview documents retain their source.
External/server error details also retain their source when no platform key exists.

The browser API is `t(key, vars, fallback)`, `getLocale`, `setLocale`, `subscribe`,
`formatNumber`, and `formatDate`. Missing keys fall back through Chinese, English
and an explicit fallback; they never display a raw key. Formatting applies to
presentation only, never input values, IDs, payloads, parameter JSON or ISO data.
New editable defaults may start in the selected language and then become user data.

`msg(key, vars)` retains a translation key until presentation. `uiError` retains
that metadata on errors and `errorMessage` retrieves it without rewriting unknown
external errors. These values belong only in UI state; requests and storage retain
ordinary domain values and strings. Pure interpolation getters must not refer to
the message being replaced.

`i18n-bindings.js` updates explicitly registered leaf nodes and presentation
attributes. `bindText` accepts a key or pure getter; `bindValue` accepts a retained
message or pure getter. `bindAttribute` allows aria labels, title, placeholder and
alt, never input values. Bind a label's text span, not its parent containing an
input. Rebinding replaces the prior binding, including static shell ownership.
Weak references permit detached nodes to be collected. There is no DOM observer,
user-content translation or panel reconstruction on a locale change.

Locale resolution is account preference, local preference, browser language,
then `en`. A failed preference read leaves the current local choice usable.
Hydration is versioned and writes are serialized/coalesced: stale responses cannot
replace a newer choice or another account. Switching preserves Workspace, Session,
form nodes and values, focus, iframe identity, frozen Verify drafts and unresolved
request keys. The only associated write is the account locale preference PUT.

`0011_user_locale_preferences.sql` is additive and must follow
`0010_project_budget_routes.sql` before publishing the new locale API/assets.
The table is owned by `catalog_users`; reads and writes use the current principal
and recheck active/auth_version in SQL. Better Auth tables, invitations, projects,
Turns, providers, gates and billing are unchanged. Production migration/deployment
and authenticated acceptance are separate from local implementation validation.

`npm run check:ui` validates matching bilingual keys and interpolation placeholders,
literal translation references and the explicit HTML declaration inventory.
JavaScript CJK exceptions have been removed; the remaining CJK inventory records
HTML fallback text. An English literal guard rejects new prose/action literals
beyond reviewed technical exceptions (CSS classes, keyboard names, sandbox flags
and developer errors). It is a conservative tokenizer, not a JavaScript parser or
proof of complete semantic coverage; computed keys and copy quality need review.
New product text must add both translations and preserve the explicit binding.

Local browser fixtures cover language changes during pending operations, failed
storage, account races, preserved editable values/user content and iframe identity.
They also verify unchanged product request payloads and no locale-triggered product
POST. Those assertions are local fixture evidence, not proof of production provider
execution or authenticated production acceptance.
