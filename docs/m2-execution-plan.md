# M2 Pi Session、持久 Turn 与文件版本执行清单

更新：2026-09-07。M2 的目标是：受邀用户在 ready Workspace 中提交消息后立即获得持久 `turn_id`，浏览器断线不终止执行；平台可恢复事件、取消、Pi Session 和已提交文件版本，且未知副作用不会自动重放。

平台继续拥有 Session、Turn、事件、Revision、Checkpoint、Runtime generation、模型凭据与预算。项目内 Pi 只通过 Tool Bridge 修改当前项目资产；项目文件不能签发平台事件、保存收据或终态。

2026-09-07 最新[真实产品 Turn 本地审查](evidence/runs/m2-product-turn-provider-disabled-20260907053121020/primary-review.json)已用三类真实容器、D1/DO/R2 和产品 release assembly 完成项目初始化及两个连续 provider-disabled Turn。首轮保存后强制删除 Project 与 Trusted Pi Sandbox；第二轮在新 actor 中以首轮 receipt 同时恢复 workspace 与 Session，保持文件摘要并推进 Session 摘要，再保存新 Revision。首轮执行期间创建的两个排队 Turn 均在派发前取消，Workerd 重启后仍保持 cancelled 且没有 checkpoint。随后再次销毁容器并删除第二轮 Session blob；第三轮在分配 Sandbox 前以 `turn-base-unavailable` 结束，持久化标记 `turn-checkpoint-unknown`，没有第三个 manifest 或新 Sandbox。第二 fixture 租户的五类产品 API 越权访问均在 Runtime 前返回 404，Runtime 的七个完整身份字段逐项篡改均返回 409，拒绝前后 R2 与容器集合不变。三轮重启恢复一致，模型预算与外部 Worker fetch 均为 0，容器全部清理。回执 SHA-256 为 `3b077263a36f5753cf54fec1f06101a0ff968ef4b6f0a10afada952231c5229c`。验收只在生成的 `m2-provider-disabled-v1` 镜像中启用候选 release；产品 Dockerfile、完整产品配置和 staging 仍失败关闭。[完整产品拓扑本地审查](evidence/runs/m2-product-topology-v2-local-20260907/primary-review.json)继续证明八个 Durable Object、R2、两个私有 Service Binding 和三类容器镜像可由 Wrangler 启动，且不依赖 M0 镜像或 `Dockerfile.local`。没有模型调用、云部署或容器滚动。

## 当前已实现切片

- `services/turn/` 定义与领域无关的 Session、Turn、Event 和 Checkpoint receipt。
- SQLite Durable Object 原子账本在事务中保存完整状态，`sync()` 完成前不返回成功；响应丢失后按原幂等 intent 回读，不生成第二个 Session 或 Turn。
- Workspace 范围内一次只 claim 一个 Turn，跨 Session 串行。claim 重放返回相同 `dispatchId + runtimeGeneration`，后续 Runtime 必须以同一组合去重。
- Runtime 事件校验 Turn、dispatch、generation、时间和 16 KiB payload 上限；`event_id` 同内容重放返回原 sequence，异内容冲突。
- 排队 Turn 可直接取消且永不 claim；运行中取消先持久化 `cancelling` fence。执行结束先进入 `checkpointing`，只有不可变 Checkpoint receipt 提交后才产生 completed / failed / cancelled / interrupted 终态。
- `beginCheckpoint`、保存成功和保存失败都支持同一 payload 重放；执行结果与持久化结果分别记录。保存失败会保留 execution outcome、写入明确错误并释放活动 Turn，不会留下永久 `checkpointing`。
- 持久状态恢复执行嵌套结构、引用、连续 sequence、active Turn 和终态不变量检查；任一损坏均 fail closed。只读 replay/snapshot 不再为了读取而写回账本。
- Gateway 显式拒绝缺失或非法 `Idempotency-Key`；Session/Turn 重放返回 200，新建分别返回 201/202。对外响应和快照移除请求摘要、幂等键、dispatch capability 及 actor auth version。
- WorkspaceAgent 在每个 Turn RPC 再校验已确认的 M1 ready projection、完整 scope、generation 与自身 DO 名称；Catalog ready 不是进入错误 actor 的唯一防线。
- TurnDispatcher 核心按 `turn_id + dispatch_id + runtime_generation` 校验完整 Runtime receipt 后才写入事件。首次 accept 响应丢失时只 observe；只有 Runtime 明确返回 absent 才以同一不可变 dispatch 重发。终态必须同时携带底层进程已停止、写入已 fenced 的证明，以及 Checkpoint 成功或失败收据；执行错误和保存错误分栏记录。
- TurnAlarmLoop 已冻结 alarm 调度策略：先持久设置 DO alarm，再提交 queued/cancelling 状态；alarm handler 在任何 Journal 或 Runtime transition 前预置下一次 reconciliation；运行/取消中按固定间隔观察，终态立即唤醒以 claim 下一队列项，同一实例的并发 alarm 共享一次 tick。Workspace provisioning 与 Turn 各自持久化逻辑 deadline，再把单一 DO alarm 设置为两者最早值；任一侧清除或完成只清自己的 deadline 并重新计算。[共享 alarm 与 Turn engine 本地证据](evidence/runs/m2-shared-alarm-local-20260907/primary-review.json)包含两次真实 Workerd SQLite alarm 运行、重建、清除语义和 schedule 失败不提交 Turn 的测试。`WorkspaceTurnEngine` 现已装入 WorkspaceAgent；统一路由先推进到期的 provisioning、重读权威状态，再执行或延期 Turn，最后始终重新合并物理 alarm。缺少 Workspace 状态的孤立 Turn wake 只清唤醒、不伪造 scope，journal 保留用于审计。
- Turn 取消现在由 journal 原子返回本次事务是否首次建立 cancel fence；只有事务胜者调用一次 `runtime.cancel`，同时到达或重放的请求只观察相同 dispatch。该行为已覆盖并发测试并绑定在共享 alarm 证据中。
- `services/turn-runtime/` 已增加独立的产品 Runtime 编排 core，不复用 M1 blank Workspace 初始化器或 M0 probe supervisor。每个 actor 绑定完整 `scope + session + turn + dispatch + generation`，在第一次外部 await 前持久化 message digest 和 execution reservation；丢失 start 响应后只 observe，取消先写单次 fence，执行终态先持久化停止证明，再调用可注入的 Checkpoint 物化端口。Runtime 事件时间必须位于本次执行窗口内，单次观察最多 2,048 项，累计持久事件不超过 2 MiB；事件 ID 只由完整 identity 与 host sequence 派生，重放时同序号异内容会冲突。[本地产品 Runtime core 证据](evidence/runs/m2-product-turn-runtime-local-20260907/primary-review.json)覆盖 SQLite reopen、scope/payload 冲突、事件去重、late completed cancel 拒绝、checkpoint 响应丢失、Dispatcher 集成和分层 R2 object key。新增的 R2 Revision adapter 把规范项目归档和静止 Pi Session 分别按摘要写入不可变 blob，再写入绑定完整 identity、parent 与执行终态的 manifest；所有对象都回读校验。R2 receipt 只是待提交材料，只有 Workspace TurnJournal 原子记录该 receipt 后才是产品 `saved`。提交前失败可以重试；提交后响应丢失以 journal 当前状态为准。[本地 Revision 证据](evidence/runs/m2-turn-revision-local-20260907/primary-review.json)包含单元故障矩阵和真实 Workerd SQLite DO + 本地 R2 重启复验。
- Trusted Pi execution adapter、Sandbox 原生进程 adapter 与容器侧 turn host 已形成独立本地候选。平台先写入绑定完整 identity、消息和输入 Session 摘要的只读 control，再以固定 Node 程序和固定 process ID 启动；host 只调用受控 Pi facade，把 assistant、tool 与 provider 状态写入有序 running 文件，静止后先写输出 Session，再写 terminal 摘要。只有 Sandbox supervisor 明确观察同一进程退出、exit code 为 0 且 Session 摘要匹配，Runtime 才生成停止证明；进程登记丢失时即使结果文件完整也保持 `unknown`。项目 control 不能选择模型、system prompt、skill、工具或凭据；host 在 release options 之后显式写入已经校验的输入 `snapshot`，没有输入时写入 `undefined`，release 不能另行提供恢复快照。候选 release 固定 `gpt-5.6-luna`、Responses API、文本输入、Simulation Skill 与七个远程项目工具；模型 transport 和工具 bridge 都绑定同一不可变 Turn identity。独立 Trusted Pi Dockerfile 锁定 Sandbox 0.12.9、Pi 0.85.0 与 Pi Server 0.85.0，使用镜像内真实 Node 路径和同目录 release 装配。真实三容器 provider 关闭验收确认 Pi Session 启动、503 观测、冻结、Revision 保存和重启恢复；活动产品入口仍加载失败关闭模块，真实付费模型和云 VM 尚未执行。
- Tenant 范围的 `TenantModelBudget` SQLite authority 与私有 Model Proxy gate 已形成独立本地候选。它按稳定的 `scope + session + turn + generation` 汇总预算，Runtime `dispatchId` 变化不重置额度；每次调用保守占用输入上界加最大输出，分别限制 reservation attempt、实际 dispatch 次数和回合累计 Token。只有 durable dispatch fence 的首次返回可调用 provider；响应丢失、`unknown` 或 usage 缺失保留完整占用且不自动重放，只有可验证的 provider request ID 与 usage 才缩减占用。短期 HMAC capability 在 Trusted Pi outbound 边界由平台签发，绑定完整 Turn、提交用户及 auth version、实际容器、固定 provider/model、policy version 和每次调用上限；Pi 容器接触不到 capability key。内部 `/v1/responses` 只由 named service entrypoint 承载，拒绝调用方选择 model、provider、credential 或 base URL。固定 OpenCode Go adapter 重建认证与模型字段，限量缓冲 SSE，并在看到唯一 completed/incomplete 终态、provider request ID 与可核对 usage 后才结算及返回原始字节。[本地模型预算与代理门禁证据](evidence/runs/m2-model-budget-local-20260907/primary-review.json)覆盖早期预算原语；[产品发布链证据](evidence/runs/m2-product-release-chain-local-20260907/primary-review.json)覆盖 provider、Pi transport、能力票据、组合调用与完整 Wrangler 拓扑。两个发布开关默认关闭，凭据未写入配置，未调用任何模型。
- Tool Command 已冻结 exact-shape 协议和 SQLite 行级账本。read/read_page/write/edit/list/search/bash 都绑定完整 scope、Turn、dispatch、command、deadline 与参数摘要；每个 Turn 一次只允许一条活动命令。只有首次持久 `accepted → dispatched` 返回一次执行许可，响应丢失、`absent` 或 `unknown` 后只能观察同一 `effectId`。终态 receipt 必须绑定相同身份且同内容重放，冲突收据 fail closed；终态清除最高 1 MiB 的输入正文，只保留摘要和不超过 16 KiB 的结果证据。运行收据另存最后观察时间，供后续 watchdog 使用。
- ToolDispatcher 已把上述账本与 Project 文件 effect 适配层连接：`authorized=true` 才调用 execute，任何 transport 或 receipt 校验异常先把同一 effect 标为 unknown，再向上返回错误；重入携带账本保留的 command 与 digest，只调用 observe。适配层只向 helper 发送 deadline、operation 和 arguments；tenant、Turn、dispatch、command、effect 身份由平台生成并核验，helper 不能签收据。exit 4、启动后 absent 和写/edit 输出歧义保持 unknown；合法工具拒绝返回 terminal failed。read/list/search 的结果在 16 KiB 内继续内联；超过 16 KiB 且不超过 1,114,112 bytes 时，由平台 `ToolArtifactStore` 物化为不可变 JSON Artifact，Tool Ledger 只保存公开 receipt。write/edit/bash 的大结果仍失败关闭，不能借 Artifact 绕过未知副作用规则。
- 大结果 Artifact 已完成本地纵向候选：Project Sandbox 只返回 UTF-8 JSON 结果，不持有 R2 binding 或对象 key；Tool Bridge 在终态写入 Ledger 前用完整 `scope + turn + dispatch + command + effect` 派生 Artifact identity，固定单例 SQLite DO 在首次 R2 await 前写入 fence，并以 `If-None-Match: *`、回读字节数和 SHA-256 确认对象。相同 effect 的重放只能返回同一 receipt，内容改变冲突；R2 响应丢失只能用原 `operationId + inputSha256` reconcile。WorkspaceAgent 先校验自身 actor 与 scope，Gateway 再按 Catalog 当前所有权保护 `GET /api/workspaces/{workspaceId}/artifacts/{artifactId}`，公开层只接受 artifact ID 并返回回读复核后的 JSON，不接收或泄露 R2 key。Trusted Pi host 只从已完成工具的严格 JSON 结果中提取合法 receipt，失败工具必须携带 `artifact=null`；Product Runtime 再验证 receipt 后写入 `tool.completed`，用户端工具卡只用当前 Workspace 与白名单 artifact ID 构造“查看完整结果”链接。`project_read_page` 以 UTF-8 字节偏移分页，首段返回完整文件 SHA，后续段必须回传该 SHA；文件在分页间变化、偏移落在多字节字符中间或 JSON 转义后超出内联上限都会拒绝或缩页。[分页、Artifact 与 UI 本地证据](evidence/runs/m2-read-page-artifact-ui-local-20260907/primary-review.json)验证 20,000 字节文件以 3 页完整读取、20,146 字节 Artifact、单对象稳定重放、300 项 M2 回归及 33 项 host/runtime/browser 定向测试。该证据不覆盖 staging、云 R2、跨租户并发或 Artifact GC。
- Project Sandbox 内已有 one-shot Python 文件适配器候选：从固定 Workspace root fd 出发，以 `dir_fd + O_NOFOLLOW` 遍历所有目录分量，读写、列表和搜索均限制大小、数量、UTF-8、路径、receipt 与 deadline；写入使用同目录临时文件、`fsync` 和原子 `replace`。原子替换前的拒绝返回 failed；替换已经发生后的路径竞争、deadline 或同步异常统一返回 unknown，避免上层将已发生的写入自动重放。
- Project Workspace 已有规范归档与恢复候选：只接受规则文件和目录，固定 USTAR 元数据与稳定字节顺序，拒绝 symlink、hardlink、设备、非 NFC/越界路径和 `.riffology`，单文件最多 32 MiB、归档最多 56 MiB、条目最多 4,096。恢复先在 `/workspace/.riffology` 控制区提取，再重新冻结并逐字节核对输入，随后才在 Pi 启动前安装目录项；`/workspace` 是独立挂载点，不能用跨挂载 rename 冒充原子切换。身份派生 token、文件锁、保留的输入归档与成功 marker 共同处理并发和重放。R2 reader 会回读实际对象字节，并限制文件归档与 Pi Session 合计不超过 64 MiB。`ProjectWorkspaceLifecycle` 只向由完整 Turn identity 派生的 Project actor 恢复，并在执行终止后从同一 actor 冻结。[本地 Workspace 归档证据](evidence/runs/m2-workspace-archive-local-20260907/primary-review.json)连续两次跨容器恢复相同摘要和内容，错误 actor 被拒绝；该证据不包含云 R2 或真实 Pi Session。
- SQLite Project effect supervisor 在 native start 前持久化 immutable start digest 与 `prepared` fence；同一 effect 后续 start 只回读，响应丢失或 native absent 后只能 observe。running/unknown/exited 状态跨 DO 请求保留，exited stdout/stderr 清除 start payload 后可从磁盘重开恢复；损坏行 fail closed。[Native adapter 与产品镜像候选](evidence/runs/m2-native-project-effect-20260907/primary-review.json)适配 SDK 0.12.9 没有 stdin 的实际接口，以 root-only control file、固定 wrapper、固定 process ID 和 `autoCleanup=false` 启动，wrapper 读取后降至 uid 10001 执行文件 helper。随后已把 adapter 与 supervisor 装入 `ProjectToolSandbox`，并增加 actor/scope/command/effect/expiry 全绑定的 HMAC capability；[本地真实 Sandbox SDK RPC 证据](evidence/runs/m2-project-sandbox-rpc-20260907/primary-review.json)验证了直接 actor RPC。[本地 Durable Tool Bridge 证据](evidence/runs/m2-tool-bridge-local-20260907/primary-review.json)连续两次由 SQLite Tool Ledger 授权一次、派生 Tool Bridge 与 Project Sandbox actor、签发 capability、执行容器写入并持久化终态；错误 Bridge actor、改写 payload 和重复终态均按契约处理。新增的[Trusted Pi 内部 HTTP 证据](evidence/runs/m2-trusted-tool-http-local-20260907/primary-review.json)再连续两次验证 Trusted Pi 容器 → HTTPS outbound interception → HMAC/actor 校验 → named service entrypoint → Tool Bridge DO → Project Sandbox 的完整本地路径；同一容器提交错误 scope 时在账本前返回 403。Trusted Pi 候选现用受控 Session scope 与 Runtime identity 构造六种 Tool Command，组合测试确认请求经 outbound HMAC 后只到达派生 Tool Bridge actor。Bash 的原生执行已在 Project helper 路径实现；仍需真实云回合中的 watchdog、取消与资源上限验收。
- 双 Sandbox 已加入本地候选类和配置：平台从 scope、Turn、dispatch 的完整 SHA-256 派生两个不同且符合 63 字符限制的 actor ID；可信 Pi 无项目目录和 ambient env，只允许精确的内部 Model Proxy 与 Tool Bridge POST 路径，启用 HTTPS interception，并移除来路身份头后由 Worker 重建签名；项目 Sandbox 无网络、无允许 host、无 ambient env。锁定 SDK 0.12.9 的源码证明 outbound `context.containerId` 等于该具名 Sandbox DO 的 `ctx.id.toString()`，服务端据此校验 scope 派生 actor；SDK 升级必须重跑该门禁。新增完整本地 Wrangler 候选声明八个 DO、R2、两个 named service binding 与三类容器，并经 `wrangler deploy --dry-run --containers-rollout=none` 识别；M1 初始化容器直接使用当前受审查的 `Dockerfile.cloud`，不依赖 M0 缓存镜像或 `Dockerfile.local`。Turn 和 provider 开关都固定为 `false`。该配置未进入 staging，也未创建 M2 云 Container application。`envVars={}` 也不替代启动后的真实环境快照和敏感变量拒绝验收。
- 已接入受 Better Auth 与 Catalog 所有权保护的 HTTP API。`Accept: text/event-stream` 返回最长五分钟的 SSE 观察窗，支持 `Last-Event-ID` 和 `after_sequence` 恢复；每次轮询都重新检查 Catalog 当前权限，关闭 reader 只停止观察。首轮权限在返回 HTTP 200 前检查；流建立后的撤权以 `stream.closed: authorization_changed` 表达，因为此时不能再改变 HTTP 状态码。普通 GET 继续返回分页 JSON fallback。
- 事件游标超出保留窗口时，SSE 发送 `snapshot.required` 后立即关闭，不会越过缺口继续推新事件。客户端必须 GET Workspace 快照并以快照的新游标重连；Journal 已按 oldestSequence 检测缺口，超过保留窗口时返回 `snapshotRequired=true`，用户端已接快照恢复。长期事件归档仍待完成。
- ToolDispatcher 已装入本地 `ToolBridgeAgent`；Trusted Pi 的内部 `/v1/tool` 只由 named Worker service entrypoint 暴露，固定 POST/host/path/content-type，30 秒窗口 HMAC 绑定容器 ID、时间与正文摘要，并再次按 command scope 派生 Trusted Pi 与 Tool Bridge actor。真实本地 Workerd/双容器链路已通过。TurnDispatcher 现由 WorkspaceAgent alarm 调用独立 ProductTurnRuntime actor；生产 release factory 已把 R2 reader、Project Workspace restore/freeze、Trusted Pi native host 与 Revision checkpoint 组装到同一完整身份，并在 gate 或 binding 不完整时于 actor/container/R2 解析前拒绝。为避免留下永久 `queued`，现有本地、staging 和完整产品候选配置仍固定 `M2_TURNS_ENABLED=false`；提交回调在解析 WorkspaceAgent actor 前返回 `turn_runtime_not_ready`/503，只有精确字符串 `true` 才进入 journal。[本地门禁证据](evidence/runs/m2-turn-admission-gate-local-20260907/primary-review.json)覆盖失败关闭、零 actor 解析和开启后的精确转发。该门禁已部署为 staging Worker 版本 `beeb20f0-6346-405e-88ea-632ea87863d8`；[云部署证据](evidence/runs/m2-turn-admission-gate-staging-20260907/deployment.json)确认版本变量、现有 DO/Container 绑定、`containers-rollout=none`、主页 200 和未登录拒绝。新增完整 M2 binding、容器镜像和 release 候选仍未部署，真实登录后的 SSE 与 Pi 执行尚未形成云验收。
- Turn claim 现在在 WorkspaceAgent journal 的同一 SQLite 事务内冻结最新 workspace head 和当前 Session head。两个收据随 Dispatcher、Product Runtime、Trusted Pi execution/native adapter 一路传递到 schema v2 Revision manifest；Pi 恢复字节必须匹配 Session 收据，Revision commit 必须先回读并校验基线 manifest、files blob、Session blob、scope、generation 与 Session 归属。[本地基线版本链证据](evidence/runs/m2-turn-base-lineage-local-20260907/primary-review.json)覆盖 genesis、跨 Session workspace head、同 Session 连续恢复、Runtime 幂等摘要、旧状态迁移和持久状态篡改拒绝。父版本不再来自项目 snapshot，也不由 Pi 输出选择。

| `POST` | `/api/workspaces/{wid}/sessions` | `{title}` + `Idempotency-Key`，创建持久 Session |
| `POST` | `/api/workspaces/{wid}/sessions/{sid}/turns` | `{message}` + `Idempotency-Key`，返回 202 与持久 Turn |
| `POST` | `/api/workspaces/{wid}/turns/{tid}/cancel` | 排队直接取消；运行中保存取消 fence |
| `GET` | `/api/workspaces/{wid}` | 当前 Session、Turn 与活动回合快照 |
| `GET` | `/api/workspaces/{wid}/files` | 最新已保存 Revision 的只读文件元数据；不返回内容或内部身份 |
| `GET` | `/api/workspaces/{wid}/diff` | 最新 Revision 相对父 Revision 的只读元数据差异；不返回文件内容或内部身份 |
| `GET` | `/api/workspaces/{wid}/events?after_sequence=N&limit=M` | 默认返回按单调 sequence 回放的分页 JSON |
