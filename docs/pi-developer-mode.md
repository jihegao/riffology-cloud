# Pi 开发者模式与测试

## 发布状态（2026-09-19）

实现为现有测试账号提供 Pi 执行路径及独立、持久的费用观察账本。新模式不设应用层金额准入额度，保留单轮运行边界、身份校验、并发控制、取消与资源释放检查。

**本次发布保持 Agent 执行入口暂停。** 发布前对线上原始 G5 token 账本进行了只读检查：同一测试账号有 4 条 `unknown / pending` 且没有终态的调用，还有 2 条 `failed / provider-failure / pending`，有 request ID 但用量未知。后两条的笼统分类也不足以证明上游执行结束。此次没有调用付费模型，没有清理、重置、结算或重新放行这些记录。临时只读 Worker 已删除。

本地模型预览仍可使用。此前用户已报告 Queue、Mesa 预览能运行、修改参数影响预览、刷新后参数保留；这属于用户手动确认，不能替代新的 Agent 端到端验收，也不能证明云端 Experiment/Evidence 已通过。

## 行为与边界

- `PI_DEVELOPER_POLICY_JSON` 严格限定一个 tenant/user，必须显式启用；私有 `PI_DEVELOPER_BUDGET` 绑定负责开发者 token 与费用观察记录。
- 新项目默认使用 Pi；已持久绑定 Managed 的项目保留 Managed。历史 G5 项目/回合不能被重新解释为开发者任务。
- Workspace 在提交时保存开发者标记。模型代理核对实际 Workspace 回合、身份、运行状态与取消状态，并在费用预留后再次核对。只有这个私有授权路径可以使用 `billingMode: observe`。
- 已完整接收 `response.completed` 或 `response.incomplete`，且有有效响应身份和匹配状态时，缺少 usage 只影响费用确认。原始预留金额与固定价格 profile 仍然保留，费用显示为未知而非零。
- 记录到的费用是按固定价格和 provider usage 计算的观察值，`invoiceVerified` 始终为 false，不是供应商账单结算。
- 502/504、超时、断流、通用 provider failure、尚未结束的调用继续阻止后续模型调用。限制覆盖账号所有开发者项目，并只读检查原 G4/G5 token 账本；新项目、policyId 或新账本不能绕过历史执行未知。
- 同一请求只能 dispatch 一次。持久化 ACK 丢失、服务重启或刷新页面不触发模型自动重试。费用投影从固定预留和持久终态生成，避免第二次写入丢失导致金额被错误清零。
- 原 G4/G5/Production Money 账本不迁移、不清零；历史窗口开关、Managed 策略、云端仿真/服务开关保持原值。

## 当前可测试的步骤

1. 打开现有 Queue 或 Mesa 项目，进入“模型预览”，运行一次。
2. 修改一个可见参数，重新运行；确认结果相应变化。
3. 刷新页面；确认参数保留，预览仍能运行。
4. 回到项目列表，再进入同一个项目；确认模型与参数仍在。
5. 查看对话区：Pi Agent 入口应保持暂停。适用开发者模式的项目会显示“执行结果尚未确认”提示；刷新或新建项目不应解除阻断。不要为测试此状态发送或重复发送模型请求。

遇到问题，保留项目链接、步骤、可见错误文字和大致时间即可。

## 解除历史阻断后才执行的 Agent 验收

必须先取得与原始请求逐条对应的可信上游执行终态，按原记录完成核对；不要把时间经过、HTTP 超时、费用预留或新 policyId 当作终止证明。验证所有旧执行结束、资源释放和权限后，才可单独启用 `M2_TURNS_ENABLED`、`M2_MODEL_PROVIDER_ENABLED`、`PRODUCTION_MODEL_ENABLED`。`G5_ADMISSION_ENABLED` 保持 false。开关状态不等于真实 Agent 验收。

随后使用同一测试账号新建“Pi 开发者验收”项目，按顺序操作：

1. 发一条请求：“创建一个简单的单服务台排队模型，提供到达率、服务率、随机种子参数和可运行的模型预览。”只发送一次。
2. 等待 Agent 明确结束且文件保存；确认保存版本出现，预览可运行。
3. 在同一对话追加：“增加平均等待时间输出，保留现有参数。”确认基于原模型修改，保存后可预览。
4. 改一个参数并运行，刷新后再运行；确认参数和模型均保留。
5. 离开项目再返回，继续一次小修改；确认历史对话、文件和保存结果一致。
6. 若出现执行未确认、资源释放未确认或错误，停止重试并保留原项目链接。只缺费用但有可信完整执行终态时，应保留费用待核对记录，不应凭空填零。

此验收由用户主动触发真实模型请求，产生正常 provider 费用。本次自动验证只使用合成 provider 响应与本地 Workerd/SQLite。

## 维护与验证

主要回归覆盖：严格策略解析、Workspace 并发提交与重启、私有模型代理授权及中途撤销、缺失 usage 的完整 SSE 终态与畸形流、token/费用记录重启恢复、跨项目未知执行阻断、历史账本只读检查、G5 关闭时的 UI/提交一致性。原严格 provider 路径仍要求完整 usage。

私有 DO `snapshot(tenantId, identity)` 提供本轮 token 记录和费用观察值；它不是公共账单 API。部署时保留现有绑定、容器拓扑、secret 绑定与 observability，添加新 DO 导出/绑定和指定账号策略。执行开关的开放应以实际历史核对结果为依据。
