# Production model path (#46)

Implemented code candidate; **disabled and not production accepted**. No default production model, credential/account selection, live Gateway configuration, paid benchmark, deployment or ordinary-user production acceptance was performed. `docs/adr-production-model-provider.md` remains the decision context. ## Server configuration and gates

A new OpenAI path requires **all** of `M2_MODEL_PROVIDER_ENABLED=true`, `M2_MODEL_PROVIDER=openai`, `M2_MODEL_ID` matching the explicit profile model, `PRODUCTION_MODEL_ENABLED=true`, `PRODUCTION_MODEL_PROFILE_JSON`, `PRODUCTION_ACCEPTED_EVIDENCE_SHA256` matching the profile's acceptance artifact hash, the private `PRODUCTION_MODEL_BUDGET` SQLite DO binding, `PRODUCTION_MONEY_POLICY_JSON`, and the two named server Secrets. Missing/invalid settings fail closed. No model picker is exposed. The local example adds only a disabled flag and private binding/export; staging/online configurations were not changed.

`ProductionProfile` in `services/model-proxy/production-profile.ts` is the exact JSON contract: schema/profile version; inference provider `openai`; explicit model; `openai-responses`; `platform-byok`; Cloudflare account/gateway IDs; fixed secret references `PRODUCTION_OPENAI_API_KEY` and `PRODUCTION_AI_GATEWAY_TOKEN`; acceptance and privacy artifact hashes; versioned USD rate card; model input/output bounds. It cannot select an arbitrary base URL, credential name, provider or billing fallback. Profile validation and hashes prove configuration consistency, **not** that someone ran a scientific/production benchmark. The owner must provision acceptance artifacts only after authorized evaluation. The monetary policy pins the full profile SHA-256; the separate evidence gate alone cannot bypass that pin.

The money policy is `{version,period,profileSha256,caps:{turn,user,tenant,global}}`, all caps positive safe integers in **nanodollars** (USD × 1,000,000,000). `period` is an operator-selected accounting epoch, never a client value. Change the policy version whenever caps, epoch or route changes; reusing a version with different configuration rejects admission. `PRODUCTION_MODEL_ENABLED` controls stopping independently of version. Bind `ProductionModelBudget` to one globally named SQLite actor, `production-money-global-v1`; do not shard that name by tenant or period. A new deployment must explicitly add the binding/export using the deployment's migration conventions; this change does not modify remote inventory.

Rates are **upward-rounded nanodollars per token**, not a quoted model price. Configuration owners must use a dated worst applicable uncached-input and full billable-output rate for the selected model/context band, including reasoning tokens. Cached input without trustworthy price-specific details is charged conservatively at the uncached rate. Values are computed using BigInt and checked before safe-integer persistence. Hosted provider tools, media/files, background work, previous-response state, extended prompt retention and caller-paid service tiers are rejected. The adapter pins `service_tier:default`, `prompt_cache_retention:in_memory`, `store:false`, removes Pi's prompt-cache session key, and requires only custom function tools. Models/accounts that cannot honor this contract are ineligible; no fallback is attempted.

The Model Proxy recomputes the production input-bound floor as serialized text payload UTF-8 bytes plus 4096, requiring the existing `utf8-provider-payload-plus-4096-v1` bound version. The selected model's verified protocol/context limits remain an evaluation requirement; callers cannot lower the reservation by merely signing a smaller token estimate. Actor user/tenant/Turn identity comes from the server-authenticated capability, never the public payload.

## Durable ordering and failure semantics

`token reserve → money admit → money dispatch fence → token dispatch fence → one provider request → money receipt → token receipt → buffered response`.

- Token admission errors occur before any money reservation. Explicit money cap/profile/stop rejection returns a structured private RPC decision; the proxy releases an undispatched token reservation using its existing durable proof API. A thrown/lost money response is uncertainty, not that decision.
- If token dispatch explicitly reports it was never dispatched, the money ledger records an idempotent no-dispatch proof and releases it. An existing token dispatched/observe-only state, RPC exception, timeout or lost ACK is not proof and remains held.
- Money/token dispatch fences are durable before proceeding. A crash between authorities holds capacity and prevents a second provider call. A known reserved-only monetary record may continue through its first dispatch fence; a dispatched/unknown/completed call cannot be replayed. The adapter never executes tools. Existing trusted Tool Bridge receipts remain their authority.
- Cancellation after dispatch, stream loss, missing/malformed usage, 401/403/429/5xx and unknown outcomes keep the full reservation. They do not become free after a timeout or period rollover. Unfinished reservations count against all subsequent period caps; per-Turn accounting is lifetime, including old settled periods.
- A verified terminal usage receipt records a **conservative price calculation**, not an actual invoice reconciliation. Receipt replay is idempotent; contradictory usage is rejected. Existing profile/rates remain frozen even if new calls use another version. If money finish commits but token finish or HTTP response is lost, replay is observe-only and the saved money receipt survives.
- `lookup` remains private and readable while the provider is disabled. Retain policy configuration for history access. Unknown records have no automatic expiry or release operation. Resolving a true upstream unknown requires account evidence; this candidate deliberately provides no generic operator “free this charge” endpoint. Private `finish` can attach valid provider usage to an existing unknown call; full invoice adjustments/payment accounting are outside this implementation.

Records persist safe route/profile version, request ID, tenant/user/Turn scope, provider receipt ID, usage-quality classification, timestamps, no-dispatch proof and fixed failure categories. They contain no prompt, tool payload, credential or capability. Debug telemetry remains opt-in; no raw upstream error body is returned. Execution completion, task/model validity and billing evidence are separate facts; `response.incomplete` can contain billable usage without a successful modeling task.

## Protocol / privacy evidence checked 2026-09-14

- Cloudflare documents the native OpenAI Responses route and credential headers: [OpenAI provider](https://developers.cloudflare.com/ai-gateway/usage/providers/openai/). This adapter supplies explicit platform BYOK and Gateway token, preventing reliance on a stored-key/Unified Billing fallback.
- [Request handling](https://developers.cloudflare.com/ai-gateway/configuration/request-handling/) documents per-provider `cf-aig-max-attempts` and calls the setting the number of attempts. The adapter sends `1` and has no client retry loop. [Gateway settings](https://developers.cloudflare.com/ai-gateway/configuration/manage-gateway/) documents dashboard retry defaults and per-request overrides. **Acceptance must separately record the actual account's retry setting disabled and verify one upstream attempt under injected failure**; a fixture/header assertion cannot prove Gateway behavior or billing. The manifest requires that evidence before production acceptance.
- [Header glossary](https://developers.cloudflare.com/ai-gateway/glossary/) documents `cf-aig-skip-cache`; the adapter sends `true`. [Payload logging announcement](https://developers.cloudflare.com/changelog/post/2026-03-17-collect-log-payload-header/) documents `cf-aig-collect-log-payload:false`; metadata retention/access must still be reviewed separately. These controls do not promise zero retention at OpenAI.
- [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data) describe caching/abuse-monitoring distinctions. `store:false` plus explicit `in_memory` does not establish entire-chain ZDR. The model/account must pass the profile's privacy review.
- The installed Pi 0.85.0 Responses adapter uses SDK `maxRetries:0`; its provider retry helper defaults to zero. Its normal payload can contain `prompt_cache_key`; the production adapter intentionally removes that key and pins cache/tier settings. `services/runtime/controlled-pi.mjs` also fixes stream options to `maxRetries:0` and in-memory Agent settings to `retry.enabled:false` / `retry.provider.maxRetries:0`. The ordinary-user benchmark must still confirm one upstream attempt and no tool replay across the complete deployed chain.

## Bounded evaluation preparation

Copy `docs/production-model-benchmark.example.json`, fill the explicit account, profile, dated price source, authorization reference, source/runtime/fixture hashes, privacy and no-retry evidence, owner targets and integer limits, then run:

```sh
node scripts/model/benchmark-plan.mjs path/to/completed-manifest.json
```

This **offline-only** command validates the manifest and prints 18 bounded task attempts (six tasks × three repetitions) with worst-case cost and stop conditions. It never reads credentials, contacts a provider or treats a string authorization reference as permission. The template intentionally fails validation while required external inputs are absent. Freeze seeded failure fixtures and expected domain checks separately, referenced by their hash. Real execution still needs explicit account-owner paid authorization and the ordinary-user project workflow in the ADR. No unmeasured throughput, price or quality claims have been made.

The local regression suite covers split/malformed/truncated SSE, normal/incomplete/tool frames, auth/rate/provider errors, missing/invalid usage, cancel/deadline, fixed route/privacy headers, monetary caps/period/reprice prevention, and actual Workerd token/money crash windows, proof releases and restart/stop behavior. It is protocol/state evidence, not the six-task quality benchmark or public-operation readiness.
