## 接口与兼容要求

- 保留现有单次实验、Run 身份和不可变结果；研究级 Experiment 在其上扩展分组关系。历史记录不得因升级被改写或重新执行。
- Model Spec 继续绑定保存版本；实验冻结版本、有效参数、seed 和环境。后续模型编辑不能改变历史实验输入。
- 执行完成、模型有效性、结论证据有效性分别记录。失败、被否定的模型结果、旧版本结果保留标记，不混入有效汇总；旧结果仍可查看。
- 导出从冻结持久状态构建，包含结果摘要和可核验引用，不含供应商凭据、会话 Cookie、平台能力令牌、内部控制状态或跨项目数据。
- 双栏和展示深度复用同一模型、实验及 Preview 状态；新模型不能静默显示旧 Preview，服务消失后保留结果并显式重跑。
- Provider 接入保留 Model Proxy 授权、预算和审计边界；未知请求先对账，不以换供应商或新请求身份重放。运行复用保留 Trusted Pi / Project 隔离及旧执行栅栏。

## 验收与交接

每批记录源码版本、实际改动、接口兼容、验证命令和结果、证据位置、未验证环境及残余问题。分开标记「待实现」「本地通过」「云验证待完成」「完整验收通过」，不把测试替身当普通用户云验收。

- 每批运行相关定向测试；发布候选运行完整 `npm run check`，明确通过、失败和跳过。仅有文档变更时验证 diff 和链接，不触发运行时全检。
- 对应行为覆盖部分失败、取消、提交响应丢失、结构版本变化及刷新恢复。重建 UI 不得重复执行已完成任务，未知提交沿用原身份核对。
- 第 4 批使用一个普通用户创建的项目贯穿：建模 → 检查假设 → 基线 → 干预 → 多种子重复 → 追问数值证据 → 结构修改 → 刷新继续 → 导出复现。
- 独立核对 UI、持久状态和实际产物；数值结论须能追溯到正确 Run，旧模型结果不得被当作新版本结果。随机实验验证版本、输入、种子和结果关联，不要求单次指标固定改善。
- 导出参考实验在独立环境按 README 重跑，并按记录的容差验证结果；秘密及跨项目数据不得进入归档。
- #45/#34 验证桌面拖拽、窄屏切换、同服务恢复、旧版本提示、停止后结果保留与零 LLM 参数运行。
- #46 验证协议故障、usage 缺失、预算和真实建模任务；#37 验证纯聊天零项目环境启动、连续 10 轮、取消/迟到执行隔离、低容量公平性和冷路径回退。
- #35 从普通用户路径完成三个模型的创建、实验、提交、审核、冻结发布和新用户复制运行，不使用数据库直插或管理员专用造模路径。

线上部署、门禁变更和真实付费供应商验收按具体执行授权处理；本排序文档不构成充值、购买服务或扩大运营的授权。
