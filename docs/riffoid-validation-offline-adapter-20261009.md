## Offline publisher/readback adapter

`scripts/m1/riffoid-validation-offline-publisher.mjs` builds multipart metadata/module bytes and simulates ordered publication from static fixtures. It has no network transport, fetch, HTTP client, credential loader or live CLI. Only symbolic `fixture-*` account identifiers are accepted. Every trace GET/PUT is a simulated descriptor, never an executed API request. No secret values are obtained or supplied.

Independent review found two P2 issues in the first draft: incomplete Secret field validation, and an invalid `secret_key + version_id` upload fixture. Both are corrected in this delta. Baseline SecretKey descriptors now use only a strict redacted field allowlist (`name/type/algorithm/format/usages`); inline `key_jwk`, `key_base64`, `text`, `value`, nested key data and the former `secret_key.version_id` shape are rejected. Unsupported algorithm parameter shapes are rejected rather than guessed. The wire builder converts the redacted descriptor to `{name,type:"inherit",version_id:"latest"}` and uses `?bindings_inherit=strict`. It hashes wire metadata separately from source-plan metadata. Script PUT cannot pin inheritance to a fixed old version. Pre-write version-list evidence must show latest equals the frozen prior active version before even a simulated PUT; otherwise it stops. A check/read/write race is not eliminated by this fixture, and publisher quiescence remains unproved (`quietPublisher:false`). This is a contract/build demonstration, not a claim that production Secret preservation is established. [Official script upload/inheritance contract](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/methods/update/).

The simulation orders pre-write deployment/latest-version/settings/content reads, one write, then independent deployment, version list, version details, settings and content reads. It compares before/after identities, enforces one active version at 100%, checks the latest version, detects changes across the readback, and retains v2 version/content and deployment/version bindings. A lock rejects concurrent publication. A post-write rejection freezes the original identity. Timeout, disconnection or lost write acknowledgement permit only original-request GET reconciliation; a consistent current version does not clear pending, replay the write, authorize restoration or advance the cursor.

External read-only review subsequently found a third P2: unknown-write reconciliation omitted the normal path's identity ledger checks. The earlier internal “no remaining P1/P2” conclusion is superseded; its report and archive remain historical evidence, not external acceptance. The minimal follow-up extracts a pure shared identity validator used by both acknowledged publication and unknown reconciliation. A known baseline/historical version cannot acquire different settings/module hashes, and a known deployment cannot change its version. Reconciliation neither updates the ledger nor changes pending/cursor/current state. Before-fix fixture failures, repaired negative cases and a consistent GET-only case are retained with the revised handoff; external acceptance remains pending.

Readback hashes are computed from GET settings and GET content bytes, not uploader declarations or an opaque platform etag. Canonical JSON handles object key order. Module `path` is a local descriptor association; the byte length and SHA256 come from read bytes. Full fields unavailable in the reviewed public response shapes are excluded from the readback projection and explicitly listed: `keep_assets`, `main_module`, `containers`. The original full metadata remains in the upload plan. The adapter returns `fullStateMatches:false` and `quietPublisher:false`, so its fixture receipt cannot satisfy the coordinator's production publication guard. Asset binding preservation is narrower than asset inventory preservation; container references in exports are narrower than the entire application configuration. A future live adapter must establish those gaps separately, without inventing API response fields or copying upload claims.

## Fixed protocol application terminal evidence

`riffoid-validation-evidence.mjs` parses exactly two original Observe responses, A/B Run responses and one A cleanup response. It requires distinct original identities, matching run/slot/operation, exact bounded response bodies, the fixed expected primary/replay/expiry outcomes, monotonic request/receipt times, marker/cue ordering and fixed deadlines. Normal cleanup removes the two observed control rows. Timeout, network loss, lost receipt, partial result, unavailable verifier, duplicate operation, request alias or malformed response prevents terminal evidence.

The coordinator retains parsed originals, independently recomputes the certificate and binds the packet and receipt hashes. The certificate kind is `fixed-protocol-application-terminal-v1`. Its scope is only these original operations and their awaited validation call chains. Its basis also requires the reviewed source to remain unchanged: the validation path terminates before business dispatch, contains no validation background tasks, and does not create model/tool/Turn/container execution. Current budgets and unique lease prevent a second admitted protocol execution. Lease masks prove consumed admission, not terminal verification. Cleanup proves a closing tombstone/control cleanup, not the end of an unknown invocation.

Unproven fields are explicit: platform-wide invocation census, Cloudflare internal telemetry buffer drain, and late telemetry persistence semantics. HTTP Worker duration is not a platform hard wall-clock timeout; client cancellation and code `Promise.race` do not return server termination acknowledgement. [Workers limits](https://developers.cloudflare.com/workers/platform/limits/), [DO lifecycle](https://developers.cloudflare.com/durable-objects/concepts/durable-object-lifecycle/).

## Existing A-page cleanup

`validation-cleanup-ui.ts` contributes the browser helper embedded into the existing temporary UI. The original A page schedules exactly one existing cleanup after its server deadline. Early manual clicks do not spend the attempt. Once due, timer and manual action consume the same flag before any await. A single five-second client abort bounds waiting; timeout, network loss or lost receipt leaves the attempt consumed. A sleeping page past the fixed interval reports pending without sending; a closed page has no fabricated receipt. B does not schedule cleanup. No polling, new route, resource, credential, provider call or retry is added. CSP is recomputed for the embedded script and reports append so the original Run result is retained.

This guarantee is scoped to the single original A document. Browser refresh, duplicate tabs or complete browser termination destroy or duplicate document-local coordination; they do not provide a durable scheduler. Do not refresh, clone the page or issue another cleanup to resolve a missing receipt. Server tombstone protects the control transaction from repeat success, but an extra client request would still exceed the planned single cleanup attempt. No storage, browser profile inspection, or new infrastructure is introduced to pretend that this failure case is solved. A live checklist must require the one original A page to remain open and retain its attempt evidence.

At expiry the coordinator may record `stopped` without waiting for a slow control-plane deployment; that is request closure only. The temporary route/config remain for cleanup. Cleanup timing is not a sleep-based drain test. Missing cleanup leaves recovery pending. Any unknown journal remains frozen and cannot emit terminal or restore evidence; extending diagnostic closure is still a user decision, not silently granted by this implementation.
