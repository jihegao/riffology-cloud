## 1. 设计目标与交付边界

用户端帮助用户从官方模型或空白项目进入 Session，完成修改、观察、运行和结果追问。平台管理端帮助运营人员发布官方模型、了解租户与运行状态、处理额度和账务问题，并追溯操作。

设计以本仓库的独立产品基线为准。极简会话界面保留“项目导航、对话、按需打开的 Workspace Panel”三个层次，主界面不展开成完整 IDE。Browser 作为内置插件承载预览，Files、Changes、Runs 提供核心辅助能力。

界面必须表达三层归属：平台核心工作台，平台提供的 Pi / Skill / 工具及 Browser 内置能力，项目内的模型、应用和实验产物。Pi 使用平台能力修改项目，不构建登录、账单、运行调度或 Browser 外壳。机场图、保障参数与指标属于项目应用；具体边界及当前原型待改项见[职责文档](platform-project-boundary.md)。

原型展示一个名为“林知遥”的示例用户及机场保障项目。模型、会话、运行、图表、账单、租户、管理事件均为 mock；金额、单价和额度是设计示例。原型不连接真实 LLM、仿真、身份认证、支付或租户隔离服务。管理端与用户端的切换仅用于评审，生产用户不能通过此入口取得管理权限。

本文第 2–9 节规定完整的页面与交互要求；当前交付范围见第 1.2 节。页面存在不表示页面中的全部生产能力已经接入。原型实际操作与验证结果以配套验证清单为准，未验证的要求不视为已通过验收。

### 1.1 按产品阶段开放

| 阶段 | 用户端 | 平台管理端 |
|---|---|---|
| 基础 MVP | 邀请登录、个人空间、空白项目与机场 Starter、Session、Files / Changes / Runs、Browser 插件、真实用量和运行额度 | 平台概览、个人租户与额度、运行诊断与停止、操作审计；固定 Starter 的发布资料 |
| 首个付费版本 | 完整官方模型目录、固定版本复制、余额、充值、消费明细、回合预算、订单与退款 | 官方模型版本管理、价目表、支付对账、待核对用量、退款调整 |
| 后续按需求开放 | 团队和教学空间、成员与项目授权、成员消费额度、订阅 | 对应空间管理、教学角色及套餐运营 |

基础 MVP 可在“用量与余额”位置提供用量和资源额度，但不显示可支付的充值入口。原型可以评审首个付费版本的界面，同时在相关界面明确“示例 / 演示”性质。未来团队与教学能力不出现为能够执行的空菜单。

本次已交付用户端和平台管理端共 12 条 hash 路由的本地 HTML / CSS / JavaScript 交互原型。项目、会话、界面偏好、示例余额和管理操作等大部分演示状态保存在当前浏览器的 `localStorage` 中；右上角“重置示例数据”可恢复初始状态。

| 范围 | 当前原型提供 | 仍属于设计或待接入能力 |
|---|---|---|
| 页面与导航 | 用户端 6 页、管理端 6 页，跨端评审入口、桌面及移动布局 | 真实登录、平台管理员认证和服务端授权 |
| Workspace | 明确的平台 / 项目内 Pi 职责、Browser / Files / Changes / Runs 空状态和禁用动作 | Python / SimPy 执行、真实文件、Diff、运行与 Browser；未用机场演示数据冒充运行结果 |
| 其他官方模型与空白项目 | 模型目录与详情、选择固定版本的复制交互、独立的演示项目上下文和空态 | 实际模型文件包复制、运行环境、各模型的预览和实验；原型未运行这些模型 |
| Session | 示例消息、工具活动、预算、取消、Session 切换及本地状态反馈 | Pi Agent、LLM 调用、真实回合调度和跨客户端恢复 |

| 未提供的故障交互 | 设计文档保留处理要求 | 保存失败重试、支付状态不明确，以及真实保存恢复流程均未实现 |

本地评审原型的 Workspace 不预置机场图、仿真指标、文件、Diff、Run、费用或恢复结果。Browser / Files / Changes / Runs 可以切换视图，但在没有真实服务时只显示不可用原因；消息输入、运行和下载等动作保持禁用。其他页面中的目录、账单和管理数据仍是示例，只用于评审信息架构。

2026-09-07，生产静态入口 `services/web/` 已开始独立接线，不复用上述 `ui/` mock 状态。本地切片支持从真实项目列表打开 ready Workspace，读取持久 Snapshot 与 Event，创建、切换 Session，提交、幂等重试和停止 Turn，并显示 provider 与保存状态。assistant delta 按 sequence 排序去重，最终 message 优先；工具 started/updated/completed 合并为安全文本生命周期卡。项目页读取脱敏的 published 官方模型目录，模型卡可直接打开并预选固定版本，新建弹窗可选择空白或固定版本；目录可刷新，撤回或失败会清除未提交的旧选项，首次提交失败后则冻结原选择/body/key。项目列表显示“空白项目”或“官方版本 · 独立副本”。生产管理端也已接全状态模型目录、草稿创建、验证、发布和撤回；mutation 使用持久幂等 intent，页面仍只管理元数据；受限内容包安装已有 Runtime 本地候选，但上传和云接线尚未提供。可信项目 hash 在重新读取当前租户项目列表后才恢复 Workspace，刷新可重新建立 Snapshot/Event 观察；无效或不属于当前列表的项目 hash 不进入 Workspace。界面固定说明：平台负责身份、Session、Turn、预算、保存和恢复；项目内 Pi 只通过受控工具读写本项目文件并运行仿真。服务端已有有界事件窗口和 `snapshot.required` 协议；生产端收到该事件会关闭旧流、按当前 view generation 重读 Snapshot 和有界事件页，再从新 cursor 建流，旧项目响应和重复恢复被丢弃，失败不进入无限重连。官方模型受限内容包安装已有独立 Runtime 本地候选；生产 Diff、Files/Runs Panel 与 Browser 插件仍未接入。该切片未部署，产品 Turn 门禁仍关闭。

### 1.3 本地预览

在仓库根目录执行：

```sh
npm run dev
```

打开 [用户工作台](http://127.0.0.1:4173/#/workspace) 或 [管理控制台](http://127.0.0.1:4173/#/admin)。静态服务使用 Node.js 内置模块，无需安装依赖即可预览；浏览器验证依赖单独通过 `npm ci` 安装。

顶部“用户端 / 管理端”切换评审视角。Workspace 只展示未接服务的空状态；其他页面的修改只影响当前浏览器示例数据，使用右上角重置入口可恢复初始项目、余额和管理记录。

### 1.4 统一的示例价目表

用户端用量详情与管理端只读价目表统一使用 `demo-2026-09`，单位为人民币 / 百万 Token。该表仅用于检查金额、分类、明细与汇总的界面一致性；正式结算币种、实际售价和商业政策仍待确定。

| 互斥计费类别 | 示例单价 / 百万 Token |
|---|---:|
| 普通输入 | ¥40.00 |
| 缓存输入 | ¥4.00 |
| 输出 | ¥200.00 |

缓存输入不再计入普通输入。分类金额按 `用量 × 对应单价 ÷ 1,000,000` 计算，保留分类计算精度，总额一次舍入到分，0.5 分向上取整。例如 12,500 普通输入加 1,750 输出得到 ¥0.50 + ¥0.35 = ¥0.85。未知用量保持待核对，不按零费用处理；此示例无真实模型调用或扣费。

## 2. 信息架构与导航

### 2.1 用户端

```text
用户端
├── 工作台 /workspace
│   ├── 项目与 Session 导航
│   ├── 对话与消息输入
│   └── Workspace Panel：Browser / Files / Changes / Runs
├── 我的项目 /projects
├── 官方模型库 /library
├── 用量与余额 /billing
├── 设置 /settings
└── 登录 /login
```

项目是长期工作的入口；Session 是项目中的对话。打开项目恢复最近一次 Session 与已保存状态。项目导航下列出最近 Session，可以新建或切换 Session；同一个 Workspace 同时执行一个 Agent 回合，其他 Session 的回合显示排队。

个人模式使用“个人空间”及用户名称，避免要求用户先理解 Tenant。项目归属、消费归属出现在项目详情和账单明细中。后续开放多个空间时，空间切换器位于全局导航顶部，切换后重新展示目标空间数据；已启动任务继续归原空间。

### 2.2 平台管理端

```text
平台管理
├── 概览 /admin
├── 官方模型 /admin/models
├── 租户与额度 /admin/tenants
├── 运行与故障 /admin/runs
├── 账务与对账 /admin/billing
└── 审计日志 /admin/audit
```

管理端具有独立的标题、导航和角色标识。跨租户运维列表始终显示所属租户，详情保持对象名称、范围和状态可见。查看概览不默认打开任一用户项目。

### 2.3 原型路由

所有路径在本地原型中采用 hash 路由，例如 `#/workspace`、`#/admin/models`。导航、刷新、后退和直接进入已知路由应保持一致。无效路由显示可返回的入口，不展示空白页。

路由只是定位页面。生产版本的用户身份、租户归属和平台管理权限须由服务端校验，隐藏导航或拦截前端路由不构成授权控制。

## 3. 视觉与布局规范

### 3.1 视觉方向

采用暖白内容区、浅灰绿页面背景、深墨正文和翠绿强调色。用户端以阅读和输入为主，管理端提高信息密度，二者共用字体、间距、状态、按钮和表单语言。

| 项目 | 设计规则 |
|---|---|
| 背景 | 暖白卡片与浅灰绿底色分层，避免多个竞争性的高饱和区域 |
| 正文 | 深墨色，主要正文 14–16 px，次要说明不低于 12 px |
| 字体 | 系统无衬线字体优先，中文清晰；代码和标识采用等宽字体 |
| 强调 | 翠绿用于主要动作、选中态和进度；每个区域通常一个主要动作 |
| 警示 | 琥珀表示需处理或受限，红色表示失败或不可逆操作；均附文字或图标 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 px 的节奏，页面主要内容区保持呼吸空间 |
| 边界 | 细边框区分区域，适量圆角；不靠重阴影构建信息层级 |
| 数字 | 指标和金额采用等宽数字，单位与时间范围始终可见 |

颜色方案是视觉语义，最终色值必须通过实际对比度检查。不可仅通过绿色、红色区分成功失败，亦不可用过淡正文表示必读的收费或错误信息。

### 3.2 用户端布局

桌面端采用约 220 px 的导航、可伸缩对话区和按需打开的右侧 Panel。对话正文保持适宜阅读宽度；输入框固定在对话区底部，不遮挡最后一条消息。顶部显示当前项目、平台配置的模型和工作状态，单主供应商阶段不展示模型下拉选择器。

辅助 Panel 默认关闭；Browser 第一次就绪时可以打开一次，之后尊重用户的关闭选择。Browser / Files / Changes / Runs 共享一个 Panel 容器，不同时铺开四列。关闭 Panel 仅收起视图。

### 3.3 管理端布局

管理端使用固定导航、页面标题、摘要指标、筛选工具条及主表格。重要操作通过行内入口打开详情抽屉或确认弹窗，避免在表格中直接修改影响多个租户的设置。

概览指标只保留能引导处理的汇总，例如活动租户、运行状态、待处理问题和待核对金额。每张指标卡标明时间范围、单位和数据更新时间；“实际扣款”“预留”“待核对”分别呈现，不合并为一个消费数。

## 4. 用户端页面设计

### 4.1 登录 `/login`

目标是让受邀用户进入个人空间。表单提供账户信息、邀请提示、提交状态和具体的失败说明，不放置团队创建或套餐购买的前置步骤。

邀请无效、登录信息无效、网络不可用分别说明处理方式。提交期间禁止重复提交，失败后保留可安全保留的输入。原型登录必须标明演示进入，不暗示验证了真实账户。

### 4.2 我的项目 `/projects`

项目列表展示名称、简短说明、最近活动、保存状态、运行状态和可选的官方来源版本。来源标明“官方模板版本 · 独立副本”、空白或用户上传，不把复制内容统一标成 Agent 生成。列表、归属与生命周期操作属于平台；项目内文件与应用属于用户资产。默认按最近活动排序，支持名称搜索与状态筛选。

“新建项目”允许选择空白或固定版本的官方模型，并填写项目名称。创建成功进入新项目 Session；环境准备中时显示当前阶段。创建失败保留表单与来源版本，重试不能生成重复项目。

列表项的主要动作是“打开项目”。重命名等操作放在次级菜单；删除放在详情或更多菜单中，显示项目名称及文件、结果和活动任务的影响。删除不会删除空间余额和必要账务记录。项目创建、重命名、删除的反馈必须与被操作对象对应。

空列表显示“创建第一个项目”和机场 Starter 入口。无搜索结果显示清除筛选；权限变化导致项目不可访问时返回项目列表，不能从缓存继续展示内容。

### 4.3 官方模型库 `/library`

目标是帮助用户判断模型适用性，并从固定版本开始自己的项目。卡片包含模型名称、场景、简述、版本、适用问题和状态；分类与搜索帮助发现模型，不以模型数量制造复杂导航。

模型详情按以下顺序呈现：

1. 解决的问题、适用范围和主要假设。
2. 预览图或录制演示、参数与输出指标。
3. 当前选择版本、运行要求和验证记录。
4. 已知限制、作者、许可证和导出权限。
5. “复制此版本创建项目”与目标个人空间、项目名称。

“复制此版本创建项目”复制明确的版本，成功后进入独立项目并保留来源版本。平台维护官方目录与发布，项目内 Pi 仅修改独立副本，不能回写官方版本。浏览和复制不展示 AI 计费提示；真正运行计入运行额度，后续请求 Agent 才产生 AI 用量。验证记录应描述检查内容，不能仅以“已验证”暗示科学有效性。

已撤回版本不能用于新建，说明原因并提供可用版本。既有项目不会自动更新或被删除。新版本提示支持“从新版本新建项目”，不提供首版尚未定义的自动合并按钮。

### 4.4 工作台 `/workspace`

Session 保持主要视觉层级。消息包含用户输入、Agent 回复、折叠工具卡、运行卡、错误恢复卡和回合摘要。工具卡显示动作、目标、状态与必要输出，默认不展开完整日志。

输入框支持文本、附件和当前 Browser 上下文引用。空白输入不能发送；文件附件在写入成功后才显示可用。上下文以可移除的简短标签呈现，用户知道当前问题引用了哪个预览。首个付费版本在输入附近显示回合预算，并可查看调整说明。

提交后立即显示待处理状态；运行中提供“取消回合”。回合结束后显示文件变更摘要、保存状态、关联运行和最终费用状态。用户取消、供应商失败、等待输入和保存失败具有不同文案，不能统一显示“已完成”。

| 组件 | 内容与交互 |
|---|---|
| 项目 / Session 导航 | 项目名称、当前 Session、最近 Session、新建 Session；切换不取消当前任务 |
| 对话区 | 可读消息、工具活动、保存摘要、关联运行、恢复卡；长内容可折叠 |
| 消息输入 | 多行输入、附件、上下文、预算、发送 / 取消；提交反馈可被读屏感知 |
| 回合摘要 | 本次新增 / 修改 / 删除文件，已保存版本，运行入口，已结算或待核对费用 |
| Browser Panel | 平台插件外壳显示版本、观察时间、页面刷新、预览服务重启 / 停止及观察状态；内容边界内显示项目应用 |
| Files Panel | 文件树、文件预览、下载 / 导出；缺失或不可预览文件提供具体反馈 |
| Changes Panel | 本回合文件列表与文本 Diff，新增 / 删除有明确文字，不只使用红绿 |
| Runs Panel | 平台通用运行管理：类型、状态、输入版本、项目计划中的参数与种子、实际进度、日志、产物与停止入口；业务计划由项目提供 |

机场 Starter 的项目应用在 Browser 内容边界内展示到达、等待、保障、离场流程，当前参数、时钟、资源占用和关键结果。这些页面、参数表单与业务图表由 `app/` 提供，可由项目内 Pi 修改，不是平台对所有模型固定提供的功能。Browser 外壳仅负责承载、访问、生命周期与观察。用户修改参数提交给项目应用后端，由它持有仿真状态并反馈操作结果；平台运行状态另外显示。

关闭 Browser Panel、停止 Preview、禁用 Browser 插件是三个操作。关闭只影响布局；停止结束预览服务；禁用在设置中停止插件实例并撤销相关能力。Browser 观察失败时显示“观察暂不可用”，Session、已保存文件和既有结果保持可用。

项目应用里的“暂停仿真”只暂停仿真时钟，服务仍在运行；平台“停止预览服务”结束 service Run。两者使用独立状态与按钮。Runs 的实验确认展示项目计划中的参数和种子，不内置“4 组 / 6 组”等领域配置。当前原型仍存在这两类混合，后续按职责文档调整，本次仅更新设计要求。

### 4.5 用量与余额 `/billing`

顶部展示可用余额、有效预留、当期已结算 AI 消费以及运行额度。预留附简短解释，待核对金额单列，不能表现为已经完成的消费。

消费记录按项目与回合汇总。详情展示调用的模型、输入 / 缓存 / 输出等计费类别、实际用量、对应单价、执行时价目表版本、净金额及调整记录。Token 数量与金额分别显示，运行额度不以 Token 替代。

首个付费版本提供充值：选择金额、确认支付信息、订单处理中、确认入账或失败。支付结果不明确时显示“正在确认付款”，提供查询状态和订单入口，不鼓励再次付款。用户可查看订单、退款和导出明细；样例价格必须紧邻金额标明。

预算不足时说明“已保存当前进度；补充余额或调整预算后可继续”。充值或预算修改不会自动继续旧回合，用户返回回合后显式继续。余额不足仍可查看和导出已保存内容。

### 4.6 设置 `/settings`

基础 MVP 提供个人资料与空间信息、Workspace 的 Browser 插件开关、默认回合预算或平台资源额度说明。首个付费版本显示默认预算与账务说明入口。

插件设置明确作用于当前项目或 Workspace，不能将局部开关表现成全账户设置。保存成功说明生效范围，失败保留待保存输入；离开有未保存更改的表单时提示可放弃或继续编辑。

默认预算仅影响之后的新回合；已启动回合保留其已授权预算，调整当前回合需在对应回合中明确操作。个人模式不显示成员管理、组织角色、BYOK 或多模型供应商配置。

## 5. 平台管理端页面设计

### 5.1 概览 `/admin`

展示活动租户、活动 Workspace / Run、失败与中断、待核对用量等运营摘要。每项异常链接到已应用相应筛选的列表。将“需要处理”置于一般趋势之前，提供最近运行和最近审计操作。

运行活跃不等于仿真成功，消费估算不等于收入入账。图表与卡片标明口径和时间范围；数据暂不可用时使用缺失态，而非显示为零。

### 5.2 官方模型 `/admin/models`

列表按模型名称、场景、版本和发布状态筛选。详情展示介绍、假设、参数、指标、验证资料、许可证、发布记录，以及固定版本的摘要。

草稿可编辑；验证通过后进入可发布状态。发布确认展示准确的模型和版本，说明发布后该版本内容固定；后续修改从新版本草稿开始。撤回必须说明原因，并确认“阻止新建使用，已有项目保持可用”。撤回后仍保留版本与审计记录。

原型中的验证和发布操作只演示状态转换，不能冒充真实的模型运行检查或线上发布。

### 5.3 租户与额度 `/admin/tenants`

列表展示租户名称、个人模式、状态、项目数量、资源占用和可用余额等运维信息。详情展示成员身份的必要摘要、额度、运行分布和操作历史，不默认展示项目文件、对话或预览内容。

额度调整采用表单，显示当前值、新值、生效范围与原因。暂停或恢复租户需要确认对象及具体影响；“暂停新增工作”和“停止已有任务”不可混为一个不明确操作。已开始任务按产品资源策略处理，并保留保存状态反馈。

本计划不开放管理员身份读取用户内容，租户详情不提供“进入用户工作台”或读取文件、对话、Preview、业务结果的入口。将来若增加内容协助，须另行实现用户授予的项目范围、期限、撤销和审计，不能将管理员角色本身视为授权。

### 5.4 运行与故障 `/admin/runs`

运行列表支持按状态、租户和类型筛选，展示所属租户、项目名称、运行类型、开始时间、持续时间、进度和失败分类。详情展示运维日志、资源信息、保存状态和诊断标识。

停止操作确认具体 Run 及影响，提交后显示“正在停止”，确认结束后才显示“已停止”。有已保存的部分结果时说明其保留情况。管理员不以停止预览代替取消回合，也不把一个 Run 的操作施加于整个租户。

未知结果或运行中断提供诊断和对账入口；不提供未经判断的“一键重跑全部”，避免重复具有副作用的操作和重复消费。

### 5.5 账务与对账 `/admin/billing`

区分支付订单、消费结算、预留、待核对记录和退款调整。列表可按租户、状态和时间筛选，详情明确原订单 / 原消费、实际用量、执行时价目表和关联调整。

处理待核对项时展示已有证据与缺失内容。没有确定证据不能直接标为零费用或完成结算。退款和补偿采用追加调整，要求金额、关联记录、原因及最终确认，原始消费与订单仍可追溯。

价目表发布展示版本、生效时间、计费类别、计量单位和单价。已执行请求保留其原有价格；原型金额和价目表均标为示例。不得在详情页直接覆盖租户余额数字来代表充值或补偿。

### 5.6 审计日志 `/admin/audit`

日志展示时间、操作者、对象、动作、结果、原因和关联诊断标识，支持按对象、动作或关键词筛选。详情以可读文本解释变化前后的值，同时避免输出用户项目内容、密钥或支付敏感信息。

日志只读，不提供编辑、删除或清空历史操作。允许按权限导出符合筛选范围的审计记录，导出本身同样应记录。无结果与加载失败分别呈现。

## 6. 权限与操作范围

| 动作 | 个人空间所有者 | 平台运维管理员 |
|---|---|---|
| 浏览已发布官方模型 | 允许 | 允许 |
| 创建与修改自己的项目 | 允许 | 运维身份不自动获得此权利 |
| 查看自己的文件、Session、Preview 与结果 | 允许 | 本计划不向运维身份开放用户内容 |
| 充值、查看个人账单、设置个人预算 | 允许 | 可按运维职责处理记录，不能冒充付款用户 |
| 发布 / 撤回官方模型 | 不允许 | 授权范围内允许 |
| 查看跨租户资源状态 | 不允许 | 授权范围内允许 |
| 调整租户额度、停止指定任务 | 不允许跨租户操作 | 授权范围内允许，记录原因和结果 |
| 退款调整、账务对账 | 查看自身结果 | 授权范围内允许，保留追加记录 |
| 修改或删除账本与审计历史 | 不允许 | 不提供此类操作 |

原型评审用的身份切换不改变上述产品约束。未来团队共享预算不意味着成员能互相读取项目，教学预算也不意味着学生能查看彼此作业；对应权限界面在开放阶段另行确定。

## 7. 关键流程与状态反馈

### 7.1 从官方模型开始

`官方模型库 → 模型详情与固定版本 → 填写项目名称 → 创建中 → 项目 Session → 运行或请求 Agent 修改`

复制失败保留版本和表单，重试指向原创建请求。项目尚在准备时可以阅读进度；完成后显示初始已保存版本。`ui/` 原型模拟完整流程；`services/web/` 已接真实目录元数据和固定版本创建请求，但模型文件包尚未复制。

### 7.2 修改与观察

`输入需求 → 回合排队 / 执行 → 工具活动 → 保存 → Browser 就绪 → 查看 Changes → 继续提问`

回合、保存、预览和观察各自报告状态。观察失败不会将已保存的修改改写为失败。对已知版本运行并显示结果后，Agent 的结论需要区分“源码推断”“页面观察”和“运行结果”。

### 7.3 运行与停止

`选择已保存版本 → 确认参数与种子 → 运行 → 实际进度与日志 → 结果保存 → 查看 / 导出`

批量进度展示计划、完成、失败和取消数量；部分完成不显示全量成功。停止先进入处理中，保留已保存子任务结果。运行输入版本与当前编辑版本不同时显示两者关系。

### 7.4 预算与费用

`查看预算 → 发起回合 → 额度预留 → 实际消费 / 待核对 → 释放未使用额度 → 回合账单`

预算不足进入等待输入并保存当前进度。用户明确补充余额或调整预算后，再选择继续。用量未知时显示待核对及处理入口，不能在相同回合中自动重试消费。

### 7.5 统一状态语言

| 状态 | 面向用户的表达 | 恢复或后续动作 |
|---|---|---|
| 项目初始化 | 正在准备项目，显示当前阶段 | 等待；失败时重试创建步骤 |
| 浏览器连接中断 | 连接已断开，任务可能仍在继续 | 重新连接并获取当前状态 |
| Workspace 恢复中 | 正在恢复最近已保存版本 | 查看最后保存时间，等待恢复 |
| 回合排队 | 前一回合正在执行，当前回合已排队 | 查看前一回合、取消排队 |
| 回合执行中 | 正在处理；显示最近工具活动 | 取消回合 |
| 等待预算 / 余额 | 当前进度已保存，等待补充预算或余额 | 调整后显式继续 |
| 模型供应商失败 | 本次调用失败；显示失败类别和已保存情况 | 合适时继续；未知调用先核对 |
| 执行结束但保存失败 | 修改尚未确认保存 | 重试保存，查看最近已保存版本 |
| Browser 观察不可用 | 预览 / 观察状态分别说明 | 重试观察或查看文件 / 运行 |
| Run 部分完成 | 已保存完成项，列出失败 / 取消数量 | 查看部分结果，按计划重新发起 |
| 正在取消 / 停止 | 正在停止，请等待确认 | 保持状态，不提前报告成功 |
| 用量待核对 | 最终费用尚未确定，列出必要预留 | 查看详情与处理入口 |
| 支付结果未知 | 正在确认付款 | 查询订单，避免重复付款 |
| 空列表 / 无结果 | 区分尚无数据与筛选无匹配 | 创建首项或清除筛选 |
| 无权访问 / 会话过期 | 页面不可访问或需要重新登录 | 返回有权限页面或登录 |

关键错误放在受影响区域，附简短原因和一个明确动作。Toast 用于短暂成功反馈，不承担保存失败、支付未知等需要持续关注的状态。技术诊断标识放在可展开详情中，产品主流程不要求用户理解内部调度或存储实现。

## 8. 响应式与无障碍

### 8.1 视口规则

| 验证视口 | 用户端 | 管理端 |
|---|---|---|
| 1440 × 900 桌面 | 导航、对话、可选 Panel；保持可读正文宽度 | 导航、完整筛选行、表格和详情抽屉 |
| 1024 × 768 紧凑桌面 | 导航可收起，Panel 与对话宽度避免相互挤压 | 次要筛选折叠，表格内部横向滚动 |
| 390 × 844 移动 | 导航抽屉；Session / Workspace 切换；输入框保留触达空间 | 表格卡片摘要或明确的内部滚动区；详情与确认使用全屏 / 接近全屏布局 |

页面本身不产生非预期横向滚动。移动端不会同时挤压导航、对话和 Browser；切换视图保留草稿与当前状态。弹窗内容可以纵向滚动，主要动作保持可见，不与屏幕安全区或软键盘冲突。

### 8.2 键盘与读屏

所有操作可通过键盘到达，焦点可见且顺序与视觉结构一致。对话输入的 Enter / Shift+Enter 行为明确，多行输入不得因中文输入法确认而误发送。原型的实际键盘覆盖在验证清单记录。

弹窗打开后焦点进入弹窗，焦点保持在弹窗内，Escape 可关闭可取消弹窗；关闭后回到触发控件。导航抽屉与下拉菜单遵循同样的焦点规则。危险操作不默认聚焦确认按钮。

图标按钮提供可访问名称，表单标签与输入关联，错误信息关联到对应字段。页签标明选中态与控制面板，进度与状态变化可由读屏获知；流式输出采用合并播报，避免每个 Token 反复打断。

普通正文与背景目标对比度至少 4.5:1，大字与必要图形目标至少 3:1；交互目标优先采用不小于 44 × 44 px 的触达面积。图表提供指标文本或表格，动效尊重减少动画设置。未完成检查前不声称通过无障碍认证。

## 9. 评审与验收

评审首先确认用户能找到建模、运行、恢复和费用入口，再确认管理员能在明确对象范围内完成发布、诊断、额度处理和账务核对。所有可见主要动作都应有可理解的结果、错误或明确的演示说明。

配套验证清单应记录实际操作、预期、结果与证据，并覆盖三个目标视口、关键成功路径、错误恢复、取消 / 关闭等可逆动作和至少两个越界输入用例。服务端认证、多租户隔离、真实收费、持久运行与仿真正确性须在生产实现中另行验证，静态原型不提供这些保证。
